# Prime Radiant — `src/lib/prime-radiant/`

The server-side layer of Prime Radiant, the "living wiki": a git-backed vault
of Markdown pages with structured claims, read by OpenClaw's bundled
`memory-wiki` plugin in isolated mode and kept healthy by its own lint. Every
module here is SERVER ONLY unless it says "pure".

## Layout on disk

```
<box data dir>/prime-radiant/        (or $PRIME_RADIANT_DIR)
  vault/                              git repo, branch main, memory-wiki layout
    index.md  AGENTS.md  .gitignore
    entities/  concepts/  syntheses/  sources/
  prime-radiant.sqlite                state: claim_registry, review_items, runs, costs, ingest_jobs, ingest_files,
                                      claim_embeddings, judged_pairs
  settings.json                       ingest (exclude, parallel, nightly folders), cost-rate overrides, nightly
                                      schedule, Opus tier, contradiction pass, domains (absent = defaults)
  dream-worktree/                     the nightly pass's checkout of its dream/YYYY-MM-DD branch (only while it runs)
  uploads/<batch>/                    dropped documents waiting for their ingest (removed when it ends, 24 h TTL)
  dead-letter/<job>/                  dropped documents that still failed, kept for a retry (30 days)
  tmp/<job>/                          a job's private extraction scratch (removed when it ends)
```

| `state-db.ts` | `openStateDb(vault)` / `withStateDb(vault, fn)` (node:sqlite, migrated by `user_version`, v4), `stateDbExists` (what every read asks first); the claim ledger: `readRetiredLedger`, `recordRetired`, `syncActiveClaims`. |
| `plugin-wiring.ts` | `planMemoryWikiWiring(config, vault)` (pure), `memoryWikiWiringStatus()`, `ensureMemoryWikiWiring({ force })`: writes only `plugins.entries.memory-wiki.{enabled, config.vaultMode, config.vault.path}`, only when they differ, in one batch. Owner choices (plugin off, another mode or vault, agent scope, deny/allow lists) are `conflict`s, never overwritten unless forced (and deny/allow/agent scope never). |
| `service.ts` | What the routes answer: `getStatus()`, `listPages(filter)`, `getPage(rel)`, `getLint(paths)` — none of them creates anything; on a missing vault they answer `initialised: false` / empty / null — and `initialise()` (`ensureVault` + `ensureMemoryWikiWiring`, idempotent; a failed config write is a `WiringWriteError`). |
| `route-helpers.ts` | `json`, `fail(code, error, status)`, `vaultFailure(where, err)`, `ownerWriteGuard(req, what)` (session → owner cookie → same origin). |
| `writer.ts` (pure) | The Flash writer's contract: `buildWriterPrompt(items)` / `readWriterItems`, `parseWriterResponse(text, items)` (strict: one verdict per item, a dropped or garbled item fails that file alone, no JSON array throws `WriterParseError`; each `[` is tried against the last few `]`, so brackets in the prose around the array cost nothing), `buildPage(draft, sourceLabel, ctx)` (path by type, global claim ids via `allocateClaimId`, a re-ingested document updates its page in place, a VERIFIED page is never touched), `addToIndex`. | `flash-client.ts` | `FlashClient` (`complete({ system, user, maxTokens, signal })` → `{ text, usage, model }`), `createClawboxAiFlashClient` (the ClawBox AI proxy, `resolveClawaiToken` per call, a credential the proxy itself refuses noted in the shared memo), `FlashCallError` kinds (`rate_limited`, `server`, `network`, `bad_response` retryable; `no_credential`, `auth`, `refused`, `aborted` not), `completeWithRetry` (4 attempts; Retry-After plus up to 2 s of jitter, else exponential backoff 2 s → 1 min with equal jitter), `estimateUsd` (re-exported from `cost-rates.ts`). `flashClient()` answers `setFlashClientOverride(client)` first (kept in `processStore`), then `createStubFlashClient()` when `CLAWBOX_TEST_MODE=1` AND `PRIME_RADIANT_FLASH_STUB=1`, else the proxy. |
| `flash-stub.ts` | The deterministic model for the browser smoke test: a card per item from the document itself. |
| `cost-rates.ts` (pure) | `DEFAULT_COST_RATES` — the ONE rates object (`basis: "estimate"`, USD per million tokens, public upstream list rates), `readRateOverrides`, `mergeCostRates`, `estimateUsd(model, usage, rates)` (a model with no rate is 0, never another model's rate). |
| `settings.ts` | `<root>/settings.json`: `readSettings()` (never creates; a bad file or field reads as its default), `writeSettings(patch)` (strict, whole patch or nothing, `null` restores a field or a section, unknown file keys kept, atomic 0600), `readSettingsPatch(body)` (a route's patch: unknown sections/keys refused), `effectiveCostRates()`. Ingest: `exclude`, `parallel` (1–256, default 128), `folders` (absolute, ≤ 20: what the nightly pass re-reads). `nightly` `{ enabled: true, time: "03:00" }`; `opus` `{ enabled: false, capUsd: 2 (0.01–1000), sampleRate: 0.02, model }`; `contradictions` `{ enabled: true }`; `domains` `[{ name, owner }]` (the owner a domain's new pages get at ingest). |
| `review-store.ts` | `review_items`: `addReviewItem` (cleaned; the same `dedupeKey` still open or `later` answers the waiting item, `created: false`), `getReviewItem`, `listReviewItems` (status/kind/claim filter, counts), `settleReviewItem`, `closeItemsForRetired`, `countWaitingForRuns`, `safeReviewId`, `cleanCandidates`. Kinds `contradiction`, `verified-touch`, `lint`, `opus`; candidates `{ text, page, claimId?, evidence[] }`. |
| `verify.ts` | `verifyClaim({ claimId, text, by, retire, page?, evidence? })`: ONE `vaultOperation("verify: <claimId>")` — the claim becomes the verified text (`status: verified`, confidence 1, `verified {at, by}`, a human-verification evidence line, page `checked_by: human`), every `retire` id is removed from every page carrying it and listed in its `retiredClaimIds` and in the ledger (also an id no page carried), a colliding copy of `claimId` elsewhere is removed without being retired. A retired id cannot be verified again; a secret in the text is refused by the lint. |
| `review.ts` | `resolveReviewItem(id, { action: pick \| new \| later \| dismiss })` (serialised per process; pick/new verify under the item's claim id and retire every other candidate id; items about a retired id are closed; the reindex hook is told), `readResolveAction`, `createReviewItem` (a hand-raised item). |
| `gate.ts` | The verified gate: `verifiedTouches(vault, base, head)` — pages the branch changed (three-dot, against the merge base) that are verified on the base at page or claim level, judged PARSED (a re-serialisation is no touch); `gateIgnores` (`.openclaw-wiki/`, `_views/`, `log.md`, `log.jsonl`, `index.md`, every non-page); `judgeTouch` (pure). |
| `judge.ts` (pure) | The contradiction judge's prompt (`buildJudgePrompt`, the `PAIRS (JSON):` marker, `readJudgeItems`) and its strict reader (`parseJudgeResponse`: `contradiction \| compatible \| unsure`, malformed items dropped, `why` redacted). |
| `contradictions.ts` | `runContradictionPass(snapshot, { stateVault, scope, … })`: active claims (redacted) embedded with Memory Shard's embedder (`embedDocumentsWithShardEmbedder`; `setClaimEmbedderOverride`, a hash embedder under the stub), each claim in scope paired with its k = 5 nearest neighbours on other pages (`nearestPairs`), the pairs judged by Flash 40 a call (8 in flight); `contradiction`/`unsure` become review items (deduped per pair). Vectors cached per claim by text hash and embedder identity (`claim_embeddings`), verdicts per pair of texts (`judged_pairs`): an unchanged vault costs nothing. Caps: 20,000 claims, 4,000 pairs a pass. Never throws for a model: `skipped` says why. |
| `opus.ts` | The optional Opus tier: `opusClient()` (the account pool's API key or Claude account against the Messages API; `setOpusClientOverride`), `buildOpusQueue` (owed → changed → in review → sampled; never verified or human-checked pages), `runOpusTier(tx, queue, { capUsd, rates, client })` — a HARD cap (each call's worst case must fit; no rate for the model = no start), pages read get `checked_by: opus`, pages not reached `opus_pending: true`, proposed edits become `opus` review items, never edits. |
| `history.ts` | `pageHistory`, `vaultDiff({ to, from?, path? })` (a commit against its first parent, capped), `revertCommit({ sha, path? })` — the commit's patch applied in reverse under the lock and linted like any operation (`conflict`, `lint_blocked` — e.g. undoing a verification —, `dirty`, `nothing_to_revert`), one commit `revert: <sha> <subject>`. Commit ids rebuilt from hex (`safeCommitId`). |
| `runs.ts` | `runs` rows (`insertRun`, `saveRun`, `listRuns`, `settleOrphanRuns`, `anyFinishedRun`, `safeRunId`) and `readCostSummary(vault, rates, { since, runId })` — totals, by operation, by model, by run (ingest and nightly), all estimates. |
| `nightly.ts` | `startNightly(trigger, deps)` / `runNightly` (never throws): branch `dream/YYYY-MM-DD` (local date; `-2`… when taken) in a worktree beside the vault → ingest the settings' folders into it → contradiction pass (every claim the first night, else the branch's pages) → optional Opus → lint everything the branch changed (an error holds the night, a `lint` item) → the gate (a touch holds it, `verified-touch` items) → merge into `main` under the lock (fast-forward or one merge commit, re-linted for the blocking rules, put back on failure), branch deleted, `notifyVaultChanged`. Offline: the ingest and the judge are skipped and said to be. `mergeHeldNight(branch)` — the owner's merge of a held night once its items are settled. One pass a box (`NightlyBusyError`). |
| `nightly-scheduler.ts` | `start` (from `src/instrumentation.ts`), `refresh` (after a settings save), `nextRunAtMs`, `computeNextNightlyMs` — the `clawkeep-memory-scheduler.ts` shape, state in `processStore`; a slot with no vault, a pass running or an update in flight is skipped. |
| `reindex-hook.ts` | `setVaultReindexHook(fn)` / `notifyVaultChanged(paths)`: the seam to Memory Shard's incremental reindex. Called after a nightly merge, a verification and a revert; a no-op until the Shard side registers `reindexPrimeRadiantPaths` at boot. |
| `ingest-exclude.ts` (pure) | `DEFAULT_INGEST_EXCLUDES` (VCS, dependencies, caches, build output, worktrees, scratch/spike folders, agent-run archives, system folders), `readExcludeList` (strict), `compileExcludes` (`*`/`?`, case-insensitive, names only). |
| `ingest-dead-letter.ts` | Kept copies of dropped documents that still failed: `keepFailedUploads`, `dropKeptCopies`, `pruneKeptCopies` (30 days), `deadLetterRoot()`. |
| `ingest-sources.ts` | `scanFolders` (Memory Shard's `walkFiles` plus the exclude list, ClawBox's own output folders and linked git worktrees — never the vault; `excluded` counts what was left out), `readFileOnce` (one no-follow handle: size, SHA-256, bytes), `extractText` (txt/md decoded; pdf/docx/odt/rtf through the box's own `extractOne` over a private copy of the hashed bytes), `prepareText` (control characters out, redacted, capped), `sourceLabel` (home folded, redacted — the only name a document has outside the box, and a page's identity; when redaction folded something away it carries `#<12 hex>`, an HMAC of the real path under the box's own `<prime-radiant>/.label-key`, so two paths that read alike once redacted stay two pages). An upload's files are labelled `upload/<batch>/<name>`. |
| `ingest-store.ts` | Job rows, file rows (SHA-256 per file: dedupe; `source`, `attempts`, `retried_by`: the dead-letter list), `readDeadLetter` (labels only), `claimDeadLetter` (one transaction), `refreshDeadLetterCount`, `recordCost`/`readCosts`, `settleOrphanJobs` (unreached files become dead letters). |
| `ingest.ts` | `startIngest(input, deps)` → the job at once; the work runs on. One job a box (`IngestBusyError`). Scan (or, for `{ kind: "retry", retryOf }`, the claimed dead letters) → per file read/hash/dedupe/extract/redact → batches of 50 (or the character budget) → up to 128 Flash calls in flight (the settings file's `parallel`) → ONE `vaultOperation` commit per answered batch → the RETRY QUEUE: files that failed for a reason that may pass (a call that kept failing, an unreadable answer, an item the model dropped, a save that failed — not a lint refusal, a stop or a refused credential) get one more round after `REQUEUE_DELAY_MS` in half-size batches → what still fails is the job's dead-letter list (`deadLetter`, `requeued` on the job). `subscribeIngest`, `getIngestJob`, `listIngestJobs` (never create the database), `stopIngest`, `ingestFinished`, `safeJobId`. A refused credential or plan stops the job; a re-run of the same folders retries exactly what did not finish. Every dependency (client, vault, parallel, batch size, extractor, sleep, clock) is injectable. |
| `ingest-upload.ts` | Dropped files: `stageUpload` (batch id and file name rebuilt from their alphabets, written `wx`, metered, 9 MiB a file because the middleware keeps only the first 10 MiB of a body, a body shorter than its declared length refused), `stagedBatch`, `pruneStaleBatches`. |

## Routes (`src/app/setup-api/prime-radiant/`)

All owner-only through `requireSession`, `force-dynamic`, `Cache-Control: no-store`, failures as `{ error, code }`. The GETs NEVER create the vault (no folder, no repository, no state database, no config write); the app calls `POST init` when status says `initialised: false`. There is no boot hook.

- `POST init` — `ensureVault()` + `ensureMemoryWikiWiring()`, idempotent: `{ created, plugin: { state, …, wrote } }`. Owner cookie AND same origin (the MCP bearer gets 403 `owner_only`, a cross-site page 403 `cross_origin`), because it writes openclaw.json. 500 `vault_unavailable` when the vault cannot be made, `wiring_failed` when the vault is made and the config write failed.
- `GET status` — `initialised`, the vault's counts, git head, memory-wiki wiring state (reported, never written), lint summary. Not initialised → zero counts, `git: { branch: null, head: null, commits: 0 }`, a clean lint.
- `GET pages?type&domain&status&verified&q&offset&limit` — page list, no bodies (`{ total: 0, pages: [] }` with no vault).
- `GET pages/<path>` — one page: frontmatter or its errors, body, summary, backlinks, links, scoped lint. Not a page, or no vault → 404.
- `GET lint?path=…&paths=a,b` — lint report for those pages, or the whole vault (an empty report with no vault).
- `POST ingest` `{ folders: string[] }` (1–20, the folder picker's rule — `resolveFolderInsideBrowseRoot`, shared with Memory Shard) or `{ upload: <batch> }` → 202 `{ job }`. Owner cookie AND same origin. 409 `busy` (`runningId`), 412 `no_credential`, 404 `folder_not_found` / `unknown_batch` (with `index`), 400 `folder_refused` (ClawBox's own output) / `invalid`.
- `GET ingest` → `{ running, jobs }` (recent, newest first; nothing created on a fresh box).
- `GET ingest/<id>` → `{ job, deadLetter: [{ seq, label, error, attempts, bytes }] }`; 404 `not_found`. Never creates anything.
- `DELETE ingest/<id>` — stop: 202 `{ stopping: true, job }`, 409 `not_running`, 404. Owner cookie AND same origin.
- `POST ingest/<id>/retry` — a job over that job's dead letters → 202 `{ job }` (`kind: "retry"`, `retryOf`). 409 `nothing_to_retry` / `busy`, 412 `no_credential`, 404. Owner cookie AND same origin.
- `GET ingest/<id>/events` — SSE: `job` (tallies), `file` (`{ seq, label, status, pages?, reason? }`), `end` (final job, then the stream closes). A finished job answers `job` + `end` at once; a 15 s comment keeps proxies open; 404 for an unknown id.
- `POST ingest/upload?name=<file>[&batch=<id>]` — one dropped document as the raw body → `{ batch, name, bytes }`. Owner cookie AND same origin. 400 `invalid_name` / `empty`, 404 `unknown_batch`, 409 `batch_full`, 413 `too_large`, 507 `disk_full`.

- `GET review?status=open|later|resolved|all&kind&claimId&offset&limit` → `{ total, counts, items }`. `POST review` `{ kind?, claimId?, pages?, candidates?, note? }` → 201 `{ item }` (200 `created: false` when the same question waits): the owner OR the MCP bearer (the assistant may flag a fact), same origin, 412 `not_initialised`.
- `POST review/<id>/resolve` `{ action: "pick", candidate } | { action: "new", text, page? } | { action: "later" } | { action: "dismiss" }` → `{ item, commit, retired }`. Owner cookie AND same origin (a verification is a person's word). 404, 409 `already_resolved` / `no_claim` / `verify_failed` / `lint_blocked`, 400 `invalid`.
- `GET history/<page>?limit` → `{ path, commits }`; `GET diff?commit=<sha>[&from=<sha>][&path=<page>]` → `{ from, to, path, commit, files, diff, truncated }`.
- `POST revert` `{ commit, path? }` → `{ reverted, commit, changed }`. Owner cookie AND same origin. 409 `conflict` / `lint_blocked` (with `findings`) / `nothing_to_revert` / `dirty`.
- `GET settings` → `{ settings, defaults, limits, nightly: { nextRunAt }, rates }`; `PUT settings` (a patch; folders by the folder picker's rule; re-arms the timer). Owner cookie AND same origin.
- `GET costs?since&runId` → the cost summary (estimates).
- `GET nightly` → `{ running, nextRunAt, runs }`. `POST nightly/run` → 202 `{ run }` (409 `busy`, 412 `not_initialised`); `{ merge: "dream/…" }` merges a held night (409 `open_items` / `not_merged`). Owner cookie AND same origin.

## Building on it

- The ingest writer adds pages with `vaultOperation("ingest: <what>", async (tx) => { … tx.writePage(path, fm, body) … })`, allocating ids with `allocateClaimId` against `buildClaimIndex` of a snapshot read under the lock, after `redactText`/`redactPath` on everything sent to a model. Later passes calling the model go through `flashClient()` + `completeWithRetry` and record every call with `recordCost`.
- Settle a fact through `verifyClaim` (or `resolveReviewItem`), never by editing a claim's text in place.
- Anything that moves `main` calls `notifyVaultChanged(changed)` afterwards.
- A model call outside the ingest goes through `flashClient()` / `opusClient()` and records itself with `recordCost` under its run id.
