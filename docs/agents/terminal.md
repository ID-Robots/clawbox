# Terminal

The Terminal app, its tabs and device sessions, picture paste and the PTY server. Read it when you touch `TerminalApp.tsx`, `TerminalTabs.tsx`, `terminal-*` or `scripts/terminal-server.mjs`.

## Frontend (`src/components/`)

### Built-in Apps

- **`TerminalApp.tsx`** — xterm.js terminal over WebSocket PTY. A PICTURE can be pasted: it is uploaded to `POST /setup-api/terminal/paste-image` (owner-only, same-origin, raw body ≤ 9 MiB, PNG/JPEG/GIF/WebP by magic bytes; `src/lib/terminal-paste.ts`, `src/lib/terminal-paste-store.ts` — `~/.cache/clawbox/terminal-paste/`, 0700/0600, server-made names, pruned at 7 days / 200 MB on the next paste, wiped by factory reset) and the saved file's absolute PATH is what the terminal pastes, as a paste, which Claude Code turns into an image attachment. The key is plain Ctrl+V, the only one on which a browser hands a page a picture (Ctrl+Shift+V is "paste as plain text"): the key handler lets the browser have it (`isPlainCtrlV`, not on a Mac, where ⌘V carries pictures) and a capture-phase paste listener gives the shell its `^V` unless the clipboard holds a picture AND the program in front takes one — asked of the PTY server (`{type:"foreground"}` → `{taker: "claude" | "shell" | null}`, `foregroundTaker` in `scripts/terminal-foreground.mjs`: yes only when exactly ONE live member of the terminal's foreground process group — `tpgid` of the PTY's shell, never node-pty's `process` name, which is the group leader's and falls back to the spawn shell — has the terminal as its stdin, and it is Claude Code or a shell started with nothing but flags; so `cmd | less`, a wrapper script's editor, an editor Claude Code opened and every editor are a no. Bracketed-paste mode cannot make the cut, because vim and nano turn it on too, and Claude Code runs on the alternate screen as they do). The answer is reused for 500 ms only while nothing but `^V` has been sent to the shell since it was asked. A `^V` still owed goes out ahead of the next key; a held key or a second press while one upload runs is one paste; a non-owner's refusal (`owner_only`) hands the key back to their shell. An explicit paste with only a picture (⌘V, Shift+Insert, the menu's Paste on a secure origin) uploads whatever is running; Ctrl+Shift+V with nothing readable names Ctrl+V in a notice. A shell the owner ENDED (`exit`, Ctrl+D) is said as such — `terminal.exited` in the status bar, `terminal.shellEnded` in the transcript, never the ws:// URL — and is not respawned on its own: Enter or Reconnect starts a new one, while only a socket that actually dropped retries after 3 s. The right-click menu is portaled to the body on `DESKTOP_LAYERS` above the shelf and clamped above `shelfHeight()`, because rendered inside the window it sat under the shelf with Clear unreachable (the sweep of 2026-09-07). Its face is shipped, not hoped for: JetBrains Mono (`public/fonts/JetBrainsMono-*.woff2`, OFL) for the text and the Nerd Fonts symbols set (`SymbolsNerdFontMono-Regular.woff2`, loaded only when a glyph in its `unicode-range` is on screen) for powerline/devicon glyphs, with the platform's colour emoji faces behind them in `TERMINAL_FONT_FAMILY`; `loadTerminalFont()` waits (bounded) for the web font before the grid is measured, or xterm would size its cells on the fallback. The palette (`terminalTheme(ground)`) is GitHub's dark scheme — the same colours the code editor's `.tok-*` classes use — on the Coding Agent's ground (`--win-ground`, read at runtime), with a coral cursor; the tab bar (`TerminalTabs.tsx`) sits on the same ground with a coral glyph on the selected tab. A fit is HELD while a width or height transition runs on anything containing the terminal — a snap glide, the chat docking or changing width, a monitor change — and made once when the last one ends (`watchResizeTransitions`, with `RESIZE_TRANSITION_WATCHDOG_MS`, 1 s, for an end that never arrives), so a glide is one size to the PTY rather than a reflow every frame; the grid still follows an edge drag frame by frame, but the PTY hears the first size at once and then at most every `PTY_RESIZE_INTERVAL_MS` (100 ms, timed on `performance.now()`), always ending on the final size.
- A window record can carry `meta` (`openApp(appId, forceNew, meta)`); the Terminal window's command travels that way (`clawbox:open-terminal` → `meta.command`), never in shared state, so a plain Terminal opened later types nothing.
- **`TerminalTabs.tsx`** — the Terminal window: several shells as tabs, every tab's `TerminalApp` kept mounted (its PTY survives a switch; the panel is `hidden`), the first tab carrying the window's `initialCommand` and named after it, at most `MAX_TERMINAL_TABS` (8) shells per window, the close button a sibling of the `role="tab"` element, Alt+Shift+T / Alt+Shift+W / Alt+Shift+PageUp/PageDown handed up from the terminal (`onTabAction`; the Ctrl+Shift forms are the browser's own accelerators and never reach the page), closing the last tab opening a fresh one. `TerminalApp` itself gained `active` (focus + refit when the tab comes to the front) and a right-click menu (Copy — over plain HTTP through the execCommand fallback —, Paste when the origin can read the clipboard and named as Ctrl+Shift+V when it cannot, Select all, Clear; `rightClickSelectsWord` so a right click on a word selects it). The live preview still embeds the single `TerminalApp`. Terminal strings are `terminal.*` keys in the desktop translations. On the desktop (`onStateChange`, TASK-1306) every tab is a device session: the tab list with each tab's session id goes to the window's record and back as `persisted` on a refresh, a tab closed by hand (or replaced after its shell ended) is ended on the box through `endTerminalSession` (`src/lib/terminal-sessions.ts`, its own short `?end=` socket), and unmounting ends nothing. `TerminalApp`'s `persist`/`session`/`onSession` carry it: a reattach resets the screen before the replay and types no `initialCommand`; a gone session says `terminal.sessionGone` / `terminal.sessionGoneStatus` and, like an ended shell, waits for Enter or Reconnect instead of opening a fresh one; a dropped socket reattaches to the same session. Only the terminal in the focused window (`WindowChromeContext.active`) takes the keyboard. xterm and its addons load once through `loadXtermModules` however many terminals mount together.

## System Integration (`scripts/`, `config/`)

- **`scripts/terminal-server.mjs`** — WebSocket PTY server on port 3006 (plain ESM JS, started with the web server's own Node — no npx, no transpiler). Since TASK-1306 a desktop Terminal tab's shell is a SESSION that outlives its socket (`scripts/terminal-sessions.mjs`, the registry and protocol, unit-tested with a fake PTY): `?session=new` starts one and answers its id in `started`, `?session=<id>` reattaches (`attached`, then the scrollback as one `output` with `replay: true`, capped at `CLAWBOX_TERMINAL_SCROLLBACK_KB`, default 512, cut at a line start), an id that is unknown or another user's is answered `gone` exactly alike, and `?end=<id>` is the hand-close (`ended`). A session nobody is attached to is ended after `CLAWBOX_TERMINAL_IDLE_MINUTES` (default 720); one whose page never spoke on it (a reload mid-handshake) ends with its socket; each user keeps at most 32 unwatched sessions (the oldest, ended shells first, go); a shell that ended while nobody watched is kept, with its output, until the idle clock so a reattach shows how it ended. Sessions live in this process's memory: a reboot or a restart of the server ends them. No `session` parameter is the old ephemeral shell (the Coding Agent's run tail, the standalone `/app/terminal` page)
