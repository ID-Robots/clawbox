# Coding Agent: the app

The Coding Agent desktop app: home, project and run pages, the agent chart, its settings, wizards and run history. Read it when you touch `CodingAgent*`, `CodingRun*`, `CodingTeam*` or `NewAppWizardCard.tsx`.

## Frontend (`src/components/`)

### Built-in Apps

- **`AnimatedNumber.tsx`** — a figure that counts to its new value on animation frames (ease-out, `prefers-reduced-motion` jumps): the run page's tokens tile, so a number that climbs while the run works reads as progress rather than as a glitch.
- **`CodingRunTimeline.tsx`** carries the "+3m 12s" of every step ALWAYS (not on hover), and a step opens on a click (`aria-expanded`, `data-expanded`, `coding-agent-run-activity-detail`: the clock time in full, the step's kind, its whole line). **`CodingRunSummary.tsx`** draws the run's `report.md` — the closing message the runner files, or the fuller report a run wrote — as the Summary card's Markdown (`data-source="report"`), the record's own summary standing in until it loads or when there is none; the Report button and its dialog (`CodingAgentReportPreview`) are gone, and every Markdown artifact is a plain link. **`CodingRunTeamMembers.tsx`** lists (`tree={false}` on the run page, whose agent chart draws the team; `cast` hands it the board the app already read, and then it reads nothing itself), under the Agents card, the members of the team a run belongs to — from the board's cast list, each at work or done from the app's run list, polled while the run is live — and the Agents card is up for EVERY live run, helpers or not. A running status chip breathes (`coding-agent-pulse`) on the row and on the page.
- A run's ROW opens the run from anywhere on it (`coding-agent-run-row-<id>`; a control on it — Stop, the terminal glyph, a chip to another run — keeps its own meaning), its terminal control is an icon named in full for assistive tech, and Show details is a link; the row carries no helper dots, no per-type helper counts, no live-helper list, no model identifiers and no run id since 2026-10-12 — the run's page and its chart say all of that, and the row said each three times. **`CodingTeamTree.tsx`** draws the SHAPE a team takes — on the Team card before any team has worked there (a team that has is the agent chart, below), and over a team run's members when a host still asks for it — the assistant → the Coding Agent → as many workers as the board counts (capped at `MAX_TREE_WORKERS`, the ones at work pulsing in coral) → the reviewer — a sibling of the delegation and Memory Shard arts (`ct-art-*` in globals.css under `prefers-reduced-motion: no-preference`, `aria-hidden`). Its connectors' flowing dashes run PAUSED and are stepped `FLOW_FPS` (15) times a second, about a pixel a step (`useSteppedFlow`, which writes `currentTime` to animations looked up once per commit), and not at all while the page is hidden, the drawing is scrolled out of view or reduced motion is on: 60 style recalcs a second down to 15, and none unseen. The New App card sends on Enter in either textarea (Shift+Enter is a new line; an IME composition is left alone).
- The Coding Agent's desktop icon is the Material `smart_toy` glyph — the same glyph the finish card's Open button uses.
- **`NewAppWizardCard.tsx`** — the "A new app for your desktop" card (the chat composer's + button and the Coding Agent home; the + button first reads `coding-agent/status` and, while `setupComplete` or `enabled` is an explicit `false`, opens the Coding Agent app on its wizard instead — `dispatchOpenApp("coding")`, not maximized — because the assistant cannot delegate the build the card composes until the owner has been through that wizard; a status it cannot read opens the card, never a dead button, and the Coding Agent's own hand-off through `NEW_APP_EVENT` is not gated, since that app already sits behind its wizard — `chat-new-app-gate.test.tsx`) has two modes: a NEW app (name, what, starter → `buildNewAppPrompt`) and an EXISTING project (the rows of GET /setup-api/coding-agent/projects; the chosen one's last run is shown, and "what should the next run do?" becomes `buildResumeProjectPrompt` — a message that tells the assistant to run in that folder, read the last run and the commits first, rebuild a code project afterwards, and report what is left — or, with the team switch (`coding-agent-new-team`) on, `buildTeamProjectPrompt`, which asks for `coding_team_run` instead). `openNewAppCard({ project, team })` (`ui-events.ts`) opens the card through `NEW_APP_EVENT` with that project preselected and the switch set; `ChatPopup` keys the card on the detail so a second opener gets a fresh card. The example copy is a small-business app (an invoice generator), in every locale.
- **`coding-agent-graph.ts`** / **`CodingAgentDiagram.tsx`** / **`CodingAgentLiveAgents.tsx`** — the agent CHART, the Coding Agent's first view (owner's brief, 2026-10-12: "when you open it we first must see the agents, like a chart; more visual, less text; when we click a reviewer, worker or any agent we see what it is doing at this moment"). `coding-agent-graph.ts` is pure (no fs, no React; STRUCTURAL input types the app's `TeamView` and `Run` satisfy, since `coding-team-board.ts` reads the disk): `teamGraph(board, runOf)` makes ONE node per real agent — the planner on the root row (with any lead turn that names no task on the board), a lane per task in OUTLINE order (`outline`: depth first in plan order, a task under the dependency it waits for last, the rest of its `depends_on` as `extra` arcs; a cycle or an unknown id is a root, never followed), the lane's agents from the cast list in the order they started (a worker opens an attempt, a reviewer rules on the one before it, a lead turn sits after the task it came after — with the lead's switch on there is one after every worker, and a root row of them was wider than the window; a board from before the list falls back to `assigned_to`/`reviewRunId`), a `task:<id>` placeholder for a task no worker has taken and `task:<id>:next` for the attempt a re-offered task waits for while the team can still give it one, and the final review in a lane of its own. State is one of `AGENT_STATES` (queued, working, reviewing, accepted, rejected, failed, done): the run's own status first (`stateOfRunStatus`: running → working, queued/draft/paused → queued, completed → done, the rest failed), then the board — the current attempt by the task's status and verdict (complete and unreviewed reads `reviewing` while the team runs and its shape reviews each task, or its reviewer is live), an EARLIER attempt `rejected` only when the task was never held or re-offered for CI (`holds`/`ciReoffers`), else what its run says. `runGraph(run)` is the run and its helpers (`helperKey` is the same while a helper is out and once it is back, so a selection survives), a few to a row. `layoutGraph` places it all on a grid where rows never share a y and two nodes of a row are a full `step` apart — nothing can overlap however many tasks and attempts (the unit test lays out eight tasks with retries in both `GEOMETRY` and `GEOMETRY_COMPACT`, the latter ≤ 360 px wide); `neighbourOf` is the arrow keys. `CodingAgentDiagram.tsx` draws it: SVG for the guide lines and edges (`aria-hidden`; dependencies violet with an arrow, retries amber, the edge into an agent at work coral and flowing — `ct-art-flow`, stepped by `CodingTeamTree`'s exported `useSteppedFlow`), every node an HTML BUTTON over it named in full with its state (`STATE_COLOR` and `STATE_ICON`, so no state rests on colour; `ct-art-live` pulses the ones at work, both rules under `prefers-reduced-motion: no-preference`), one in the tab order (roving), arrows/Home/End move, click/Enter/Space opens the PANEL (`coding-agent-node-panel`, `role="region"`): now (`describeStep`, exported by `CodingRunTimeline.tsx` so the two word a step alike), elapsed, turns/tokens/files, the task with its result or the verdict with its notes, the planner's goal, a helper's errand, the last `PANEL_STEPS` (10) steps as an embedded timeline, Open run page, Message (`CodingRunMessageBox`, only for a session that can still take one and never for the page's own run, whose header has it) and Stop (`POST coding-agent/stop`, only while held and not for a session `GET users/me` says is not the owner's — asked once a page, unknown reads as the owner, as the desktop does). Beside the chart from `SHEET_BELOW` (640 px, MEASURED) and a sheet under it below; `COMPACT_BELOW` (520) draws closer. The panel follows the arrows while open, Escape closes it and hands focus back. It POLLS NOTHING: drawn from the host's data on the host's beat, and a node whose run the host does not hold asks `runs?id=` once and again only when `refreshKey` (the host's data) moves. Its figures are chips and bars (`taskProgress`, `tokensByRole` — the cast list's settled `tokens`, a live run's own `tokensUsed`, a lead counted with the planner — and the wall time). `DiagramDetails` is a native `<details>` the words fold into, closed: the Team card's help, agents, shape, metrics and the whole board (tasks, PR, inbox, messages, log — the PR and the team's error stay above it), and a run page's Agents card. `CodingAgentLiveAgents.tsx` is home's first section (`coding-agent-live-agents`, `data-live`): one chart per team at work (`isTeamActive`) and per run at work outside a team (a team's run is drawn in its team only), the newest that was when nothing works, the delegation art and a sentence when there never was any; its team charts' Open team lands on the project's Team tab (`openTeamFor`, the workspace's one-shot `initialTab`). `RunAgentsDiagram` is the chart atop a run's page: its team with the run marked (`current`, a dashed second ring), read by id (`useTeamBoard`) when the app's list lacks it, or the run and its helpers.
- The Coding Agent window is laid out like the Claude Code web app: in a window at least `SIDEBAR_MIN_WIDTH` (860 px) wide — MEASURED with a ResizeObserver, not a CSS breakpoint, so the rail's lists exist only when shown — a left sidebar (`coding-agent-sidebar`: New, Home, Settings, the projects, the recent runs), the page beside it, and on a run's page a right rail (`coding-agent-run-rail`: figures, files changed, refusals) next to the run's story (terminal or log, summary, plan, helpers, evidence, error) — the evidence card (`coding-agent-artifacts`) sits UNDER the Agents card across the whole column, its pictures a grid (`coding-agent-artifact-images`, two to four across) rather than the stack of thumbnails the rail held, at the owner's request (2026-09-05). Narrow windows keep one column. With the rail up the header row (title, `coding-agent-state` chip, Create app, Settings) is NOT drawn at all — the rail has New/Home/Settings, the window's title bar names the app, and the owner asked for neither the name nor the state chip in the rail; the row is the narrow window's and the standalone page's. A project's page uses the window's whole width as FOUR tabs (`CodingProjectWorkspace fill`, `data-fill`), opening on TEAM — first in the row and selected by default since 2026-10-12 (owner's ruling: "Coding team needs to be the first tab in Projects before Runs"; the agents are what the owner opens a project for) — then Runs, Files and Changes: Runs (`coding-agent-workspace-runs`, the count on the tab and a live dot while one works; the page hands the list in as `runs`, so the rows stay the one list home draws under its toggle) and Team (`coding-agent-workspace-team`, the team card). The runs sat in a 22rem rail before and their rows wrapped three deep. Its git line is a bar under the title: branch · commits · newest commit, and on the right the repository's PAGE (`coding-agent-project-github`, `src/lib/github-url.ts` turns the push URL into it) with **Create PR** (`coding-agent-project-create-pr` → `POST coding-agent/git { …, action: "pr" }` → `openProjectPullRequest` in `coding-pr.ts`: the branch the project is on against the remote's default, an already-open one handed back rather than twinned, `no_remote`/`on_base` answered 409) which becomes a `PR #N` link (`coding-agent-project-pr`, also derived from a run that opened one for the same branch); a project not on GitHub yet shows a quiet Back up link (`coding-agent-project-github-backup`, through `coding-agent/git` — its own path, not the removed Files backup) in place of the green button it used to be. A LIVE run's page carries ONE card with three tabs (`coding-agent-live-card`, `data-tab`; `coding-agent-live-tab-timeline/terminal/browser`), one pane at a time: the **Timeline** first and by default, with the chat card's "Coding agent working" dots plus tokens and clock in its heading (`coding-agent-run-working`), auto-scrolled to the newest step, which is drawn in full; the **Terminal** (mounted whatever the tab, hidden otherwise, so it tails once; Open in Terminal beside the tabs); and the **Browser** the run drives (`VNCApp viewOnly`, mounted only while shown, with **Open VNC** → `dispatchOpenApp("vnc")`). The page's controls carry no Watch live, and the separate Live view is gone (the run page has the same elements). Once settled, the **timeline** (`CodingRunTimeline.tsx`, `coding-agent-run-activity`, live or settled) draws every progress line the runner recorded as the chat card's chips (`describeProgressLine`, the same `codingAgent.chat*` words), each with WHEN it happened on hover — the clock time and "+3m 12s" from the start, from `progressAt`, the runner's list of times kept one for one with `progress` (a record from before the field shows the steps and no clock) — is FOLDED under the summary on a settled run (`folded`: the card is a `<details>`, its heading the `<summary>`, closed; the steps stay in the DOM) — the Summary comes first on a settled run since 2026-10-12, because it is what the page is for and sixty timeline rows used to sit above it — the Plan card folds the same way once settled, a MET deliverable is one line, the Inputs card is drawn only when the run was given or refused a file, the run id lives in the rail under the figures, and the whole task opens in `CodingTaskDialog.tsx` (`coding-agent-run-task-open` → a `useModalDialog` modal, the task rendered as Markdown through the chat's renderer, with Copy) rather than unfolding as raw text in the header; and an **Agents** card (`coding-agent-run-agents`, folded into the Details under the page's agent chart, `coding-agent-run-details`) names the run itself and every helper — the ones still out (`activeSubagents`) and the ones back (`subagents`, a capped history the runner keeps at `closeSubagent`: type, what it did, how long it took, refused or not) with working/finished counts. A run's evidence card shows `ARTIFACT_PREVIEW` (4) pictures and folds the rest — the clips and the files too — behind `coding-agent-artifacts-toggle` (`data-folded`), because a run that screenshots every step files dozens and drawn in full they pushed the summary off the page. The whole app wears the chat's darker shell (`coding-agent-ui.ts`: `APP_GROUND` = `--win-ground`, `CARD_SURFACE`/`INSET_SURFACE`/`RAIL_SURFACE` = black veils over white hairlines, the composer's own button alphas) rather than the desktop's `--bg-deep`/`--border-subtle` pair, which read a shade lighter beside the chat.
- **`CodingAgentApp.tsx`** — the Coding Agent desktop app: harness readiness, the Test-harness button, the owner's projects (git-initialised folders and code projects), recent runs (this icon used to open an interactive `claude-ds` terminal) with summaries, and a "New app" wizard that composes one message and hands it to the mascot chat (`CHAT_MESSAGE_EVENT`) — the assistant carries on from there. Its Settings button opens the settings page embedded in the app itself; the home page leads with the agent chart (`CodingAgentLiveAgents`, see `coding-agent-graph.ts`) and then a Create New Project wizard (handed to the chat), and each project expands into its own page with a git block (branch, commits, origin — GET /setup-api/coding-agent/git?projectId=) plus that project's runs. A project row and its page carry the picture the box drew for the folder while a run worked in it (`iconUrl`, `InstalledAppIcon`), and fall back to the lettered placeholder until there is one — which is most of a fresh box. Every page but home carries ONE breadcrumb row (`CodingAgentBreadcrumb.tsx`: an arrow that goes up a level — it keeps the old Back buttons' test ids `coding-agent-settings-back` / `-project-back` / `-run-back` — then Projects › project › run, earlier crumbs as buttons, the current one `aria-current="page"`); it replaced three differently styled Back pills, and the header's Settings button no longer doubles as Back. The home list is lean on purpose — icon, name, last commit, chips, a chevron — the folder path and its copy button live on the project page. A project's page is a title row, ONE git line (branch · commits · newest commit · origin or "not on GitHub yet" · Backup) and the workspace (`CodingProjectWorkspace.tsx`): a **Files** tab — the folder as a tree read through `GET /setup-api/coding-agent/tree?projectId|directory&path=` (`src/lib/coding-project-tree.ts`, rooted at the PROJECT because a project can live anywhere the owner pointed the agent at, `.git` skipped, links not followed, `isProtectedFilePath` refused, every refusal a 404) with the shared editor (`&file=`, capped, binary flagged; `PUT coding-agent/tree { projectId|directory, file, content }` saves the OWNER's edit — a session cookie, never the MCP bearer, since the agent edits with its own tools — over a file that is already there through `writeProjectFile`, the same descriptor-by-descriptor walk as the read with O_WRONLY|O_NOFOLLOW at the end and no O_CREAT, capped at the read cap so a file opened whole is saved whole; a cut file is shown read-only because saving it would lose its tail, a save while a run works in the folder is allowed with an amber note that the run's next commit takes the edit along, and a second file tapped over unsaved changes is asked about first) and the Files app's icons from `file-icons.tsx`, plus **Open in Files** (`coding-agent-open-in-files`, folder projects only, not on the standalone page) — and a **Changes** tab: `GET coding-agent/git?…&changes=1[&ref=<sha>]` (`gitChanges`/`gitLog` in `coding-git.ts`: the working tree via `status --porcelain=v2` + `diff --numstat`, untracked files counted by hand, or ONE commit's changes via `diff-tree`, because a run commits its work when it settles and leaves the tree clean) with a picker over the recent commits, and `&diff=<file>` for one file's unified diff drawn by `DiffView` (text only, header lines folded). A ref reaches git only as a hex sha or HEAD (`isSafeGitRef`), a file only as a normalised in-project path (`safeProjectRelativePath`); the Changes tab reads nothing until it is opened and polls every 5 s while a run works in the folder. A run has its OWN PAGE (`view.face === "run"`, `data-testid="coding-agent-run-page"`) instead of a row that unfolds: status, task, project chip, controls (pause/resume/start, stop or discard, terminal, backup), a figures grid (steps, files, duration, tokens, helpers by type, commit, denials, models), helpers at work, the plan, the error, the summary rendered as Markdown, the files changed, the evidence folder (a generated clip gets a player rather than a download link — a download is not how you check what a narration says), the denied actions and an activity log. A run held to a deliverable also carries a card naming what it had to leave behind, the verdict on it and how much of its attempt budget went on it — on a run that GAVE UP that card is the only thing on the page that says what is actually absent, since the chip says only "Gave up" and the error repeats the reason — with Resume in the ordinary row of run controls beside it. A refused action's sentence (a Resume the folder is gone for, a Stop that failed) is drawn ABOVE whichever face is up (`coding-agent-action-error`, scrolled into view), never under the page — at the bottom of a run's page it sat off screen and a refused Resume looked like nothing happened; the sidebar's recent runs list every HELD run (running, paused, drafted) ahead of the settled ones whatever its age, so a run waiting on the owner is never out of sight; and the Settings page's Clear history also drops a paused run or a draft whose folder is GONE (neither can be resumed or started, and kept it was immortal). A settled run whose `leftover` is true — something it started is still listening — says so in an amber card with the Kill button beside it, because the device leaving an app's server up is a documented pattern and killing it unasked would break the pattern, while saying nothing would make it a leak nobody can see. Opened from a row's Details button, a review chip, or from outside through `dispatchOpenCodingRun(runId)` / `handoffCodingRun` + `OPEN_CODING_RUN_EVENT` in `ui-events.ts` (the desktop's finish card and the chat's run card use it). Its LIVE poll (every 5 s while a run works, a team is at work — `isTeamActive`, so a chart does not freeze between one of its runs settling and the next starting — or a pull request waits on its checks) starts no read whose previous one of the same kind is still out, asks GitHub (`gh auth status`, a process and a round trip to api.github.com) only every `GITHUB_LIVE_POLL_MS` (60 s, on `monotonicNow()` from any caller's last read, so a wall clock stepped back cannot hold GitHub unasked for the step's length), and reads nothing while the page is hidden — the box's own screen included, since its visible edge re-reads everything; mount, focus, Settings saving, an action's own re-read and the read after a run settles still read all five at once (the fifth is the team list, `GET coding-agent/team`, which the agent charts on home and on a team run's page draw from). The page's clock (`now`) ticks every `NOW_LIVE_TICK_MS` (1 s) while a run is live and every `NOW_IDLE_TICK_MS` (60 s) otherwise, so the "N minutes ago" labels keep moving, and stops while the page is hidden.
- **`CodingAgentSettingsPanel.tsx`** — the Coding Agent app's embedded Settings page. Since 2026-10-12 (owner's ruling: "too many UI items and text") it is BASICS in the open — the owner's switch, the project folder, Runs on, effort, the review pass, the real browser, the pull-request switch — and ONE closed `<details data-testid="coding-agent-settings-advanced">` (`codingAgent.settingsAdvanced`) holding four labelled groups (Ceilings, Pull requests, Teams, Pictures and speech; `codingAgent.settingsGroup*`) and a fifth, Token use (`codingAgent.settingsGroupTokens`), drawn only when the status carries `diet` with every other control moved there verbatim; the panel's error line renders outside the fold, every HelpTip is one sentence, and the panel's dead `onStatus`/`onReset` props are gone (`onOpenHistory` is accepted and read by nothing — Run history is reached from the rail and the Settings card alone, the card's own Open button and the phone's home-foot button having gone). In full, the controls are: the owner's switch for delegated Claude Code runs, the default project folder, effort, a team's model and effort PER ROLE (`coding-agent-role-models`: planner, workers, reviewers, each a model select — Default, Cheaper model, Your model — and an effort select, posting `{ roleModels: { <role>: { model | effort } } }`, not drawn for a server without `roleModels`), the per-run ceilings, the automatic review pass switch (POST /setup-api/coding-agent/enable `{ reviewPass }`), the attempts a run with a DELIVERABLE gets at it (`{ completionAttempts }`, 1–6, beside the pull-request controls because the commonest deliverable IS the pull request those switches ask for, and drawn only when the server answers with the field), the two media switches under it — `{ generateImages }` (which also draws the project's own icon and favicon) and `{ generateAudio }`, both rendered `?? true` because an older server answers with neither and both are on by default, and the real-browser switch beside them (`{ realBrowser }`, `?? true` for the same reason, with a hint saying a run drives the screen the owner can watch and that off means an invisible browser), the token diet's three selects in Token use (`coding-agent-diet-brief`, `-helpers`, `-visual-tools`: full or short instructions, always delegate or only when it pays off, browser and media tools always or only for visual work — each posting `{ diet: { <knob>: value } }` alone through the panel's write chain, `codingAgent.diet*`), and the GitHub card (device-flow login, sign-out, terminal fallback). Emits `CODING_AGENT_CHANGED_EVENT` after every saved change so an open Coding Agent window refreshes. Under the main card, **`CodingRunHistoryCard.tsx`** (drawn only when the status carries `historyRetention`): the history mode and extended's N through the panel's own write chain, what the next run will delete or archive, the transcript period per harness settings file under keep-everything, what the history weighs and the free space, the low-disk alert, Export all history, and a two-tap Clear archive.
- **`CodingRunHistoryPage.tsx`** — the Coding Agent's Run history face (the rail's Run history, the home page's link in a narrow window, the card's Open button): Older runs, which open on the ordinary run page (the app keeps them in `olderRuns` beside the polled `runs`, and a run page asked for by id that the recent list does not hold is looked up once — an older run, or the archive), and Archived runs, read-only, the summary drawn with the chat's Markdown renderer, each with its own .zip.
- **`CodingAgentSetupWizard.tsx`** — the Coding Agent's first-run wizard: intro, then the numbered steps github → project → **browser** → harness (four: the browser step was added between the project folder and the harness check). The browser step says that a run can verify its work on the device's own screen, which the owner can watch: **Enable** writes `{ realBrowser: true }` and makes the browser ready — installing Chromium through `browser/manage` when it is missing (that path runs `playwright install chromium`) and then opening it — saying in the device's own words which of the two failed and offering a Continue button rather than stranding the owner on a step whose only two buttons have just refused (the setting is written before the window is touched, so a failed launch loses nothing); **Skip** writes `{ realBrowser: false }` and is an answer, not a deferral. Both land on harness, whose **Try it once** starts the harness run and finishes setup with its id (`onDone(runId)`), so the owner lands on the run's own page rather than on home with the run a dot in the rail.

The floating live-preview terminal and the pill's "open" link are gone. The card's × (`coding-agent-activity-dismiss`, `codingAgent.chatDismiss`) hides that run's card FOR GOOD, finished or still running: the run id goes to the owner's kv store under `clawbox-chat-dismissed-coding-runs` (`src/lib/use-dismissed-coding-runs.ts` — the newest 500 kept, the device's copy re-read and merged whenever the chat opens or its window comes to the front, a store that cannot be read hiding nothing), so it stays gone across a closed chat, a tab switch, a reload, a restart and another window, and the focus moves to the neighbouring card's × (else the 🤖 chip, else the transcript). The 🤖 chip (`coding-agent-restore`, `codingAgent.chatRestore`) brings back ONLY cards that left on their own five seconds after a clean finish (`src/lib/use-coding-run-auto-hide.ts`), never one put away with ×, and is not drawn when none did. The desktop's coding finish cards hide themselves after `NOTICE_AUTO_HIDE_MS` and their Open button lands on the run's page.
