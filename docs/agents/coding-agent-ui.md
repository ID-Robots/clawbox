# Coding Agent: the app

The Coding Agent desktop app: home, project and run pages, the agent chart, its settings, wizards and run history. Read it when you touch `CodingAgent*`, `CodingRun*`, `CodingTeam*` or `NewAppWizardCard.tsx`.

## Frontend (`src/components/`)

### Built-in Apps

- **`AnimatedNumber.tsx`** — a figure that counts to its new value on animation frames (ease-out, `prefers-reduced-motion` jumps): the run page's tokens tile, so a number that climbs while the run works reads as progress rather than as a glitch.
- **`CodingRunTimeline.tsx`** carries the "+3m 12s" of every step ALWAYS (not on hover), and a step opens on a click (`aria-expanded`, `data-expanded`, `coding-agent-run-activity-detail`: the clock time in full, the step's kind, its whole line). **`CodingRunSummary.tsx`** draws the run's `report.md` — the closing message the runner files, or the fuller report a run wrote — as the Summary card's Markdown (`data-source="report"`), the record's own summary standing in until it loads or when there is none; the Report button and its dialog (`CodingAgentReportPreview`) are gone, and every Markdown artifact is a plain link. The run page has ONE list of agents — its chart (`CodingAgentDiagram`, below): the Agents card, `CodingRunTeamMembers.tsx` and `CodingAgentRosterRow.tsx`, which listed the same agents a second time under it (and polled the board on a clock of their own), went on 2026-10-29; a teammate's provider/model line moved onto its node's panel. A running status chip breathes (`coding-agent-pulse`) on the row and on the page.
- A run's ROW opens the run from anywhere on it (`coding-agent-run-row-<id>`; a control on it — Stop, the terminal glyph, a chip to another run — keeps its own meaning), its terminal control is an icon named in full for assistive tech, and Show details is a link; its review chips (`coding-agent-review-of`, `-review-loop-of`, `-reviewed-by`) are `relationChips(run)`, the same helper the run's page uses, over a `reviewerOf` Map built once per render; the row carries no helper dots, no per-type helper counts, no live-helper list, no model identifiers and no run id since 2026-10-12 — the run's page and its chart say all of that, and the row said each three times. **`CodingTeamTree.tsx`** draws the SHAPE a team takes — on the Team card before any team has worked there (a team that has is the agent chart, below), and over a team run's members when a host still asks for it — the assistant → the Coding Agent → as many workers as the board counts (capped at `MAX_TREE_WORKERS`, the ones at work pulsing in coral) → the reviewer — a sibling of the delegation and Memory Shard arts (`ct-art-*` in globals.css under `prefers-reduced-motion: no-preference`, `aria-hidden`). Its connectors' flowing dashes run PAUSED and are stepped `FLOW_FPS` (15) times a second, about a pixel a step (`useSteppedFlow`, which writes `currentTime` to animations looked up once per commit), and not at all while the page is hidden, the drawing is scrolled out of view or reduced motion is on: 60 style recalcs a second down to 15, and none unseen. The New App card sends on Enter in either textarea (Shift+Enter is a new line; an IME composition is left alone).
- The Coding Agent's desktop icon is the Material `smart_toy` glyph — the same glyph the finish card's Open button uses.
- **`NewAppWizardCard.tsx`** — the "A new app for your desktop" card (the chat composer's + button and the Coding Agent home; the + button first reads `coding-agent/status` and, while `setupComplete` or `enabled` is an explicit `false`, opens the Coding Agent app on its wizard instead — `dispatchOpenApp("coding")`, not maximized — because the assistant cannot delegate the build the card composes until the owner has been through that wizard; a status it cannot read opens the card, never a dead button, and the Coding Agent's own hand-off through `NEW_APP_EVENT` is not gated, since that app already sits behind its wizard — `chat-new-app-gate.test.tsx`) has two modes: a NEW app (name, what, starter → `buildNewAppPrompt`) and an EXISTING project (the rows of GET /setup-api/coding-agent/projects; the chosen one's last run is shown, and "what should the next run do?" becomes `buildResumeProjectPrompt` — a message that tells the assistant to run in that folder, read the last run and the commits first, rebuild a code project afterwards, and report what is left — or, with the team switch (`coding-agent-new-team`) on, `buildTeamProjectPrompt`, which asks for `coding_team_run` instead and, knowing no edition, points the assistant at the tool reply for how it hears that the team finished — a chat line on OpenClaw, the desktop on Hermes, `TEAM_SETTLE_WORD` in `mcp/tools/coding-agent.ts` — rather than promising a line a Hermes box never posts). `openNewAppCard({ project, team })` (`ui-events.ts`) opens the card through `NEW_APP_EVENT` with that project preselected and the switch set; `ChatPopup` keys the card on the detail so a second opener gets a fresh card. The example copy is a small-business app (an invoice generator), in every locale.
- **`coding-agent-graph.ts`** / **`CodingAgentDiagram.tsx`** / **`CodingAgentLiveAgents.tsx`** — the agent CHART, the Coding Agent's first view (owner's brief, 2026-10-12: "when you open it we first must see the agents, like a chart; more visual, less text; when we click a reviewer, worker or any agent we see what it is doing at this moment"). `coding-agent-graph.ts` is pure (no fs, no React; STRUCTURAL input types the app's `TeamView` and `Run` satisfy, since `coding-team-board.ts` reads the disk): `teamGraph(board, runOf)` makes ONE node per real agent — the planner on the root row (with any lead turn that names no task on the board), a lane per task in OUTLINE order (`outline`: depth first in plan order, a task under the dependency it waits for last, the rest of its `depends_on` as `extra` arcs; a cycle or an unknown id is a root, never followed), the lane's agents from the cast list in the order they started (a worker opens an attempt, a reviewer rules on the one before it, a lead turn sits after the task it came after — with the lead's switch on there is one after every worker, and a root row of them was wider than the window; a board from before the list falls back to `assigned_to`/`reviewRunId`), a `task:<id>` placeholder for a task no worker has taken and `task:<id>:next` for the attempt a re-offered task waits for while the team can still give it one, and the final review in a lane of its own. State is one of `AGENT_STATES` (queued, working, reviewing, accepted, rejected, failed, done): the run's own status first (`stateOfRunStatus`: running → working, queued/draft/paused → queued, completed → done, the rest failed), then the board — the current attempt by the task's status and verdict (complete and unreviewed reads `reviewing` while the team runs and its shape reviews each task, or its reviewer is live), an EARLIER attempt `rejected` only when the task was never held or re-offered for CI (`holds`/`ciReoffers`), else what its run says. `runGraph(run)` is the run and its helpers (`helperKey` is the same while a helper is out and once it is back, so a selection survives), a few to a row. `layoutGraph` places it all on a grid where rows never share a y and two nodes of a row are a full `step` apart — nothing can overlap however many tasks and attempts (the unit test lays out eight tasks with retries in both `GEOMETRY` and `GEOMETRY_COMPACT`, the latter ≤ 360 px wide); `neighbourOf` is the arrow keys. `CodingAgentDiagram.tsx` draws it: SVG for the guide lines and edges (`aria-hidden`; dependencies violet with an arrow, retries amber, the edge into an agent at work coral and flowing — `ct-art-flow`, stepped by `CodingTeamTree`'s exported `useSteppedFlow`), every node an HTML BUTTON over it named in full with its state (`STATE_COLOR` and `STATE_ICON`, so no state rests on colour; `ct-art-live` pulses the ones at work, both rules under `prefers-reduced-motion: no-preference`), one in the tab order (roving), arrows/Home/End move, click/Enter/Space opens the PANEL (`coding-agent-node-panel`, `role="region"`): now (`describeStep`, exported by `CodingRunTimeline.tsx` so the two word a step alike), elapsed, turns/tokens/files and — for a team member — what it runs on (`memberModelLine` over the cast list's `provider`/`model`/`modelRole`, `coding-agent-node-panel-model`; nothing on a board from before they were kept), the task with its result or the verdict with its notes, the planner's goal, a helper's errand, the last `PANEL_STEPS` (10) steps as an embedded timeline, Open run page, **Message in chat** (`coding-agent-node-panel-message` → `dispatchOpenChat({ draft: "Tell coding run <id>: " })`, the chat composer with the draft UNSENT — since 2026-10-30 the panel unfolds no text box; only for a session that can still take one and never for the page's own run, whose controls have the same button) and Stop (`POST coding-agent/stop`, only while held and not for a session `GET users/me` says is not the owner's — asked once a page, unknown reads as the owner, as the desktop does). Beside the chart from `SHEET_BELOW` (640 px, MEASURED) and a sheet under it below; `COMPACT_BELOW` (520) draws closer. The panel follows the arrows while open, Escape closes it and hands focus back. It POLLS NOTHING: drawn from the host's data on the host's beat, and a node whose run the host does not hold asks `runs?id=` once and again only when `refreshKey` (the host's data) moves. Its figures are chips and bars (`taskProgress`, `tokensByRole` — the cast list's settled `tokens`, a live run's own `tokensUsed`, a lead counted with the planner — and the wall time); `figures={false}` and `legend={false}` leave them (and the counted legend) out, which `RunAgentsDiagram` passes for the SOLO run on its own page because the page's figure tiles are the one home of those numbers (a team chart keeps its task and role bars, which the tiles do not draw), and `turnsKnown` is exported so the Steps tile prints no 0 for a live run either (once known, the tile prints `N / M` against the run's `maxTurns`, so the ceiling is visible). `DiagramDetails` is a native `<details>` the words fold into, closed: the Team card's help, agents, shape, metrics and the whole board (tasks, PR, inbox, messages, log — the PR and the team's error stay above it). `CodingAgentLiveAgents.tsx` is home's first section (`coding-agent-live-agents`, `data-live`): one chart per team at work (`isTeamActive`) and per run at work outside a team (a team's run is drawn in its team only), the newest that was when nothing works, the delegation art and a sentence when there never was any; its team charts' Open team lands on the project's Team tab (`openTeamFor`, the workspace's one-shot `initialTab`). `RunAgentsDiagram` is the run page's **Helpers** block (`coding-agent-run-helpers`, `data-kind` team|run, after the plan), drawn ONLY when the run belongs to a team (its team with the run marked — `current`, a dashed second ring — read by id with `useTeamBoard` when the app's list lacks it, and nothing while it loads; the team's own page takes this over in a later step) or sent helpers out (`runHasHelpers`: the run and its helpers, bare, no legend, no figure chips).
