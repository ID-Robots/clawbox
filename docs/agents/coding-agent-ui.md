# Coding Agent: the app

The Coding Agent desktop app: home, project and run pages, the agent chart, its settings, wizards and run history. Read it when you touch `CodingAgent*`, `CodingRun*`, `CodingTeam*` or `NewAppWizardCard.tsx`.

## Frontend (`src/components/`)

### Built-in Apps

- **`AnimatedNumber.tsx`** — a figure that counts to its new value on animation frames (ease-out, `prefers-reduced-motion` jumps): the run page's tokens tile, so a number that climbs while the run works reads as progress rather than as a glitch.
- **`CodingRunTimeline.tsx`** carries the "+3m 12s" of every step ALWAYS (not on hover), and a step opens on a click (`aria-expanded`, `data-expanded`, `coding-agent-run-activity-detail`: the clock time in full, the step's kind, its whole line). **`CodingRunSummary.tsx`** draws the run's `report.md` — the closing message the runner files, or the fuller report a run wrote — as the Summary card's Markdown (`data-source="report"`), the record's own summary standing in until it loads or when there is none; the Report button and its dialog (`CodingAgentReportPreview`) are gone, and every Markdown artifact is a plain link. The run page has ONE list of agents — its chart (`CodingAgentDiagram`, below): the Agents card, `CodingRunTeamMembers.tsx` and `CodingAgentRosterRow.tsx`, which listed the same agents a second time under it (and polled the board on a clock of their own), went on 2026-10-29; a teammate's provider/model line moved onto its node's panel. A running status chip breathes (`coding-agent-pulse`) on the row and on the page.
- A run's ROW opens the run from anywhere on it (`coding-agent-run-row-<id>`; a control on it — Stop, the terminal glyph, a chip to another run — keeps its own meaning), its terminal control is an icon named in full for assistive tech, and Show details is a link; its review chips (`coding-agent-review-of`, `-review-loop-of`, `-reviewed-by`) are `relationChips(run)`, the same helper the run's page uses, over a `reviewerOf` Map built once per render; the row carries no helper dots, no per-type helper counts, no live-helper list, no model identifiers and no run id since 2026-10-12 — the run's page and its chart say all of that, and the row said each three times. **`src/lib/coding-agent-flow.ts`** — `useSteppedFlow` and `FLOW_FPS` (15): the agent chart's connectors' flowing dashes (`ct-art-flow` in globals.css under `prefers-reduced-motion: no-preference`) run PAUSED and are stepped `FLOW_FPS` times a second, about a pixel a step (the hook writes `currentTime` to animations looked up once per commit), and not at all while the page is hidden, the drawing is scrolled out of view or reduced motion is on: 60 style recalcs a second down to 15, and none unseen (`src/tests/unit/coding-agent-flow.test.ts`). They lived in `CodingTeamTree.tsx` until 2026-10-30, when that drawing — the SHAPE a team takes, drawn before any team had worked — went with `CodingAgentDelegationArt.tsx` (the wizard's intro and the empty home drew it) and the `ca-art-*` rules: the owner's "the old team chart is a fake image", and a decorative picture of agents was the same objection. - **`coding-agent-graph.ts`** / **`CodingAgentDiagram.tsx`** / **`CodingAgentLiveAgents.tsx`** — the agent CHART, the Coding Agent's first view (owner's brief, 2026-10-12: "when you open it we first must see the agents, like a chart; more visual, less text; when we click a reviewer, worker or any agent we see what it is doing at this moment"). `coding-agent-graph.ts` is pure (no fs, no React; STRUCTURAL input types the app's `TeamView` and `Run` satisfy, since `coding-team-board.ts` reads the disk): `teamGraph(board, runOf)` makes ONE node per real agent — the planner on the root row (with any lead turn that names no task on the board), a lane per task in OUTLINE order (`outline`: depth first in plan order, a task under the dependency it waits for last, the rest of its `depends_on` as `extra` arcs; a cycle or an unknown id is a root, never followed), the lane's agents from the cast list in the order they started (a worker opens an attempt, a reviewer rules on the one before it, a lead turn sits after the task it came after — with the lead's switch on there is one after every worker, and a root row of them was wider than the window; a board from before the list falls back to `assigned_to`/`reviewRunId`), a `task:<id>` placeholder for a task no worker has taken and `task:<id>:next` for the attempt a re-offered task waits for while the team can still give it one, and the final review in a lane of its own. State is one of `AGENT_STATES` (queued, working, reviewing, accepted, rejected, failed, done): the run's own status first (`stateOfRunStatus`: running → working, queued/draft/paused → queued, completed → done, the rest failed), then the board — the current attempt by the task's status and verdict (complete and unreviewed reads `reviewing` while the team runs and its shape reviews each task, or its reviewer is live), an EARLIER attempt `rejected` only when the task was never held or re-offered for CI (`holds`/`ciReoffers`), else what its run says. `runGraph(run)` is the run and its helpers (`helperKey` is the same while a helper is out and once it is back, so a selection survives), a few to a row. `layoutGraph` places it all on a grid where rows never share a y and two nodes of a row are a full `step` apart — nothing can overlap however many tasks and attempts (the unit test lays out eight tasks with retries in both `GEOMETRY` and `GEOMETRY_COMPACT`, the latter ≤ 360 px wide);
