# Prime Radiant

The "living wiki": its vault, ingest, review, nightly pass, search and app. Read it when you touch `src/lib/prime-radiant/`, the `prime-radiant/*` routes or the `PrimeRadiant*` components; `src/lib/prime-radiant/README.md` is the module map.

## Setup API Routes (`src/app/setup-api/`)

- **Prime Radiant** (the "living wiki"): `prime-radiant/status`, `prime-radiant/pages`, `prime-radiant/pages/[...path]`, `prime-radiant/lint` — all GET, owner-only through `requireSession`, answered from `src/lib/prime-radiant/service.ts` (see `src/lib/prime-radiant/README.md` for the module map) — and `POST prime-radiant/init` (owner cookie AND same origin: `ensureVault` + `ensureMemoryWikiWiring` + the one-time `repairPluginWritesOnce`, idempotent; the app calls it when status says `initialised: false`, or — in the background — when an initialised vault's wiring still `needs-write`; no boot hook). The GETs NEVER create the vault: with none, status answers `initialised: false`, pages and lint are empty and a page is 404. The vault is `<data dir>/prime-radiant/vault` (`PRIME_RADIANT_DIR` overrides the parent), a git repo created by `init` or by the first `vaultOperation` whose every change goes through `vaultOperation` — the per-vault mutex in `processStore`, a scoped lint that refuses `secret-pattern`/`frontmatter-invalid`/`claim-id-collision`/`claim-id-retired-reuse` and puts the touched files back, then exactly one commit by `Prime Radiant <prime-radiant@localhost>` with the user's global git config switched off. Claim ids are global (`<domain>/<entity>/<fact>`) and a retired one is never reused (the page's `retiredClaimIds` plus the `claim_registry` ledger in `<data dir>/prime-radiant/prime-radiant.sqlite`). `plugin-wiring.ts` points OpenClaw's `memory-wiki` plugin at the vault in isolated mode AS A READER — six keys (`enabled`, `vaultMode`, `vault.path`, and `ingest.autoCompile`/`render.createBacklinks`/`render.createDashboards` = false: left at their defaults the plugin's first `wiki_status` compiled the vault — a "## Related" block on every page, `<folder>/index.md`, `reports/*.md` — and its lint held the night), written only when they differ, an owner's own setting reported as a `conflict` (`plugin-writes` for a writer switched on by hand) rather than overwritten; `status` only REPORTS the wiring; `init` is the one caller of `ensureMemoryWikiWiring`. The vault ignores the plugin whatever it does (`plugin-files.ts`): its files (`WIKI.md`, `inbox.md`, `<folder>/index.md`, `reports/`, `_views/`, `_attachments/`, `.openclaw-wiki/`) are never pages and are in the vault's `.gitignore`, `parsePage` drops its `<!-- openclaw:wiki:*:start/end -->` managed blocks from a body, and the nightly merge and a revert put back a page whose only change is such a block (`restorePluginOnlyEdits`); `plugin-repair.ts` takes what it already wrote out ONCE per vault (`pass_state` `memory_wiki_repair`; from init, the box's own ingest or the nightly pass) — only plugin files still exactly as it made them, never an owner's edit — in one commit `repair: …` for what HEAD held. Text and paths go through `redact.ts` before any network call (an IBAN is replaced whole, spaced or not, by its country's registered length — never its account digits as a "card"). INGEST (`ingest.ts`, README for the module map): `POST prime-radiant/ingest` `{ folders } | { upload }` (owner cookie AND same origin; folders by the folder picker's rule, `resolveFolderInsideBrowseRoot` in `src/lib/browse-folder.ts`, shared with Memory Shard's sources route) starts ONE job a box and answers 202; `GET ingest/<id>/events` is its SSE progress; `POST ingest/upload?name=&batch=` stages a dropped document (9 MiB, the middleware's body limit); `POST ingest/preview { folders }` (same guard, `resolveIngestFolders` in `route-helpers.ts` shared with the ingest POST) answers what a job over those folders would read WITHOUT reading it (`previewFolders`: the same scan, a size check and the machine-text check on each `.txt`/`.md` file's first 8 KB; documents, `skips` by reason, top folders, code projects by label) — the app shows it before Start and asks above 500 documents. `DELETE ingest/<id>` stops a job; `GET ingest/<id>` answers it with its DEAD-LETTER list (labels, never a path) and `POST ingest/<id>/retry` starts a job over exactly those files (`claimDeadLetter`, one transaction, so a second retry finds nothing). A job walks with Memory Shard's `walkFiles` plus the exclude list (`ingest-exclude.ts`: VCS, dependencies, caches, build output, worktrees, scratch/spike folders, agent-run archives, logs, test data/examples, snap/flatpak — folder-name patterns the owner may replace in `<prime-radiant>/settings.json`; a stored list equal to an earlier shipped default — `PREVIOUS_DEFAULT_INGEST_EXCLUDES`, append the old list there whenever the default changes — reads as today's defaults unless `ingest.excludeSavedWith` says it was saved after it stopped being the default, and saving the defaults stores nothing), never ClawBox's own output or a linked git worktree, and it is safe on a whole home folder: a CODE PROJECT found during the walk (`codeProjectMarker`: a `.git` folder unless `.obsidian` is beside it, a manifest such as package.json/Cargo.toml/pyproject.toml/go.mod/CMakeLists.txt, `*.csproj`/`*.sln`, a Makefile next to source) is not gone into while `settings.json` `ingest.skipCodeProjects` is on (default) — the picked folder itself is never judged, so picking a repo reads its docs; repository boilerplate (`.txt`/`.md` only) and temporary/partial files are left out by NAME (`fileSkipReason`); and a `.txt`/`.md` whose opening is machine output (`machine-text.ts`: logs — a line stamped with a date and the time to the second is a program's even when its message reads like prose —, delimited tables, hex/base64 — a one-line blob judged by its characters —, key=value dumps; when unsure KEEP) is skipped after extraction and before any model call. A drop and a retry are never filtered by name or content. Every reason is COUNTED in the job's `skips` (state DB v6 column, JSON) and shown in the progress card — nothing is dropped silently. The walk reads each file once and hashes it FIRST (a document some job already wrote pages for is skipped), extracts pdf/docx/odt/rtf with `memory-extract.ts`'s `extractOne`, redacts text and the path label, and sends 50 documents a call to ClawBox AI's Flash model (the writer keeps only SELF-CONTAINED claims — `subject.ts`: one opening with "It"/"The work" is repaired with the page's title, one opening with "He"/"They" dropped — and checks each fact's quote against the page's OWN document: another document of the call → filed under it, none → dropped), 128 calls in flight by default (`settings.json` `ingest.parallel`), jittered exponential backoff on 429/5xx, each answered batch ONE `vaultOperation` commit and each call one `costs` row priced by `cost-rates.ts` (one object, `basis: "estimate"`, overridable in `settings.json`). What fails for a reason that may pass goes on the job's own retry queue for a second round in half-size batches; what still fails is a dead letter (a dropped document's bytes kept under `<prime-radiant>/dead-letter/<job>/`, 30 days). The model is `flashClient()`: a test override, the deterministic stub under `CLAWBOX_TEST_MODE=1` + `PRIME_RADIANT_FLASH_STUB=1`, else the proxy. REVIEW, VERIFY and the NIGHTLY pass (README for the module map): the review queue is `review_items` (kinds `contradiction`, `verified-touch`, `lint`, `opus`; a `dedupeKey` keeps one waiting item per question) — `GET review`, `POST review` (owner or the MCP bearer, same origin: the assistant may flag a fact) and `POST review/<id>/resolve` (`pick`/`new`/`later`/`dismiss`; owner cookie AND same origin, because a verification is a person's word). `verifyClaim` REPLACES the claim in ONE commit `verify: <claimId>` (verified text, `verified {at, by}`, `checked_by: human`) and retires every losing id on every page and in the ledger. `GET history/<page>`, `GET diff?commit=`, `POST revert` (owner; the commit's patch applied in reverse and linted, so undoing a verification is refused by `claim-id-retired-reuse`). The nightly pass (`nightly.ts`, armed from `src/instrumentation.ts` by `nightly-scheduler.ts`, default 03:00 local, `settings.json` `nightly`) works on a `dream/YYYY-MM-DD` branch in a worktree beside the vault: ingest of the settings' folders, the contradiction pass (claims embedded with Memory Shard's embedder through `embedDocumentsWithShardEmbedder` in `memory-index-local.ts`, k = 5 nearest neighbours on other pages ABOUT THE SAME THING — `sameSubject`: same id entity, subject words alike or contained, or one naming the other's; wording alone never pairs —, Flash judge in batches of 8 with a capped terse verdict (`judgeMaxTokens`), an unreadable/empty/capped answer and the pairs an answer left out asked again in calls of 2, never resent as they were, vectors and verdicts cached in the state database), the optional Opus tier (off by default; sampled; an Anthropic API KEY from the account pool first, held to the hard `capUsd`, otherwise the owner's Claude SUBSCRIPTION through the `claude` CLI run headless — `opus-source.ts`: the pool's usable `login` account, `-p` with no tools, an empty strict MCP config, no setting sources, one turn, a temp folder, a deadline; never its OAuth token lifted into API calls — recorded in `costs` with `basis: "subscription"` at $0; either way at most `opus.maxPages` pages a night; a usage limit stops the tier for the night, a live coding-agent run makes it yield; no account → `opus_pending: true`; proposals are review items, never edits), the lint of everything the branch changed (an error holds the night), the verified GATE (`gate.ts`: a page verified on the merge base that the branch changed holds the night; `.openclaw-wiki/`, `_views/`, `log.md`, `log.jsonl`, `index.md` never count) and, when nothing holds it, a merge into `main` re-linted for the blocking rules, after which `notifyVaultChanged` hands the pages to Memory Shard's reindex hook (`reindex-hook.ts`; a no-op until the Shard side registers it). A held night keeps its branch; `POST nightly/run { merge }` merges it once its items are settled. `GET/PUT settings` (every section: ingest, cost rates, nightly, opus, contradictions, domains), `GET costs` (estimates by operation, model and run; embeddings reported as `notMeasured`), `GET nightly`, `POST nightly/run` (owner cookie AND same origin). The vault is also a built-in MEMORY SHARD source on every edition (`src/lib/prime-radiant/shard-index.ts`, Shard's chunker, embedder and budget, a store of its own at `<data dir>/prime-radiant/shard-index.sqlite`): built from `main` only (a `dream/` branch never reaches search), every hit carrying the page `path`, the page or claim `id`, `kind` and page `type`, a verified page or claim lifted by `VERIFIED_BOOST` with the score clamped to 1 (the order keeps the unclamped lift), indexed only while Memory Shard is switched on and the vault exists (`vaultIndexingAllowed`; `clawkeep/memory/enable` starts a whole-vault catch-up when it goes on, and `prime-radiant/search` answers `shardEnabled: false` with no results while it is off); `vaultOperation` hands a commit on `main` to `reindexPrimeRadiantPaths` without waiting, and a merge calls it with the merged paths. `GET prime-radiant/search` (owner-only, never creates the vault) answers it and queues a whole-vault run when there is no usable index; Memory Shard's own `clawkeep/memory/search` merges these hits with the owner's documents on the edition with no OpenClaw.
- **Prime Radiant edits**: `POST prime-radiant/pages`, `PATCH`/`DELETE prime-radiant/pages/[...path]`, `POST prime-radiant/claims`, `PATCH`/`DELETE prime-radiant/claims/[...id]`, `POST prime-radiant/claims/verify` (`src/lib/prime-radiant/edit.ts`, one `vaultOperation` each). These and the other Prime Radiant writes (resolve, revert, ingest start/preview/stop/retry incl. `{ files }`, nightly run/merge, settings, maintenance `connect`) go through `writerGuard`: the owner cookie from our own page, or the MCP bearer as the assistant (commit author `ClawBox assistant`, `verified.by: assistant`, no `checked_by: human`); revert admits the bearer only for its own commits; settings refuses the bearer `costRates` and `opus.model` (what the Opus cap measures); init, `ingest/upload` and the other maintenance actions stay owner-only.

## Frontend (`src/components/`)

### Built-in Apps

- **`PrimeRadiantApp.tsx`** (+ `PrimeRadiantBrowse`, `…Search`, `…Review`, `…History`, `…Lint`, `…Ingest`, `…Settings`, `…Costs`, `…FolderPicker`, and `prime-radiant-ui.ts` for the route shapes, `prJson` and `errorText`) — Prime Radiant, the "living wiki", on EVERY edition, pinned beside Memory Shard (`prime-radiant`, the Material `auto_stories` glyph, a product name with no `app.*` key). The first read of `GET status` never creates anything; when it says `initialised: false` the app sends ONE `POST init` (held in a ref, so a remount joins it) and shows a retry rather than looping on a refusal. Eight tabs over the `/setup-api/prime-radiant/*` family: Browse (domain/type/verified filters; a page with its claims, confidence, evidence, sources, backlinks and scoped lint), Search (`GET search`, Memory Shard's engine — a 404 reads as "not on this box yet", `shardEnabled: false` as "switch Memory Shard on"), Review (keep a candidate / write the answer / later / dismiss → `review/<id>/resolve`, plus a banner for held nights), History (a page's commits, the diff, Undo → `revert` behind a ConfirmDialog), Checks (the lint report, with split suggestions), Add documents (the Memory Shard folder picker over `coding-agent/browse`, a drop zone that refuses a type or a size over 9 MB before uploading, SSE progress via `EventSource` with a 2 s poll as the fallback, Stop, the dead-letter list and its retry), Settings (nightly schedule, contradiction pass, nightly folders, Opus on/off and per-night cap, domains/owners, exclude list, parallelism, and the nightly card: Run now, recent nights, Merge for a held one) and Costs (estimates per run/task/model; embeddings listed as not measured). Strings are `primeRadiant.*` in `src/lib/prime-radiant-translations.ts`, all ten locales; a route's `code` is worded through `primeRadiant.error.<camelCode>` with the route's English as the floor. Tests: `src/tests/components/prime-radiant-app.test.tsx`; docs: `docs-site/guides/prime-radiant.mdx`.
