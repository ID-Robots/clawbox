# Core libraries

The shared modules in `src/lib/` no single feature owns: network, the config and KV stores, `runtime-path`, auth and owner sessions, `process-store`, the gateway proxy, i18n and the browser's KV cache. Read it before you add module-level state, import `path`, read the config or KV store, or add a translation.

## Server Libraries (`src/lib/`)

- **`network.ts`** — WiFi management via `nmcli` and `iw scan`. Interface from env `NETWORK_INTERFACE` (default: `wlP1p1s0`).
- **`config-store.ts`** — JSON key-value store at `/home/clawbox/clawbox/data/config.json`.
- **`runtime-path.ts`** — Node's `path`, re-exported so the build cannot trace through it (TASK-1102). Every non-test file under `src/` imports `path` from here (`"./runtime-path"` inside `src/lib`, which keeps the modules `mcp/` imports free of the `@/` alias) and never from `"path"`/`"node:path"`, and `runtime-path-imports.test.ts` fails on one that does. The reason: Turbopack turns `path.join` onto a root it cannot know (CLAWBOX_ROOT, DATA_DIR, a request's folder) into a glob over the project, so `next build` walked `data/` (it panicked on a coding run's venv symlink) and copied its live files into `.next/standalone` (a rotated stream file killed the copy with ENOENT). A path built with a template or `+` rather than `join` goes to fs through its `untraced()` (`untraced(\`${file}.tmp\`)`), and an fs call Turbopack still flags as "tracing the whole project" gets a `/* turbopackIgnore: true */` first argument. `scripts/check-build-isolation.sh` is the proof: CI builds over a planted `data/` (a venv, a dangling link, files that come and go, and every file name `src/` can build) and fails if any trace reaches `data/`, `.clawbox/`, `.git` or a parked build.
- **`kv-store.ts`** — persistent KV store at `data/kv.json` for UI state. A read is answered from the PARSED snapshot while the file is still the one it was parsed from: the desktop reads one key of it every 2 s all day (the notice ring), and each read used to parse the whole file — every web app's `clawboxKv` data and legacy-storage copies included, values up to 256 KB each — so the poll cost more with every app the owner kept; an unchanged file is now an open, an fstat and a close. The key is `dev:ino:size:mtimeNs:ctimeNs` read through ONE descriptor (middleware's `readConfigCached` reason: a stat of the name and then a read of the name can pair one file's identity with the next file's bytes), a snapshot is kept only once the file has stood still for `RACY_WINDOW_MS` (2 s — a file rewritten in place inside one tick of the kernel's coarse clock keeps its key), and every write drops it. A reader that changes nothing gets the shared snapshot (`readKVShared`, never mutated); writers, `kvGetAll()` without a prefix and `kvReadStrict` get a copy. The snapshot lives in `process-store.ts` under `kv-store:<path>`, ONE per process: this module is compiled into the boot hook's layer as well as the routes', and a module-level snapshot was one per COPY — correct, since each checked its own against the file on every read, but two parsed copies of a file with no total size cap, the boot hook's sitting unused until its next read, on a box whose model servers need the memory more. Shared, either copy's read serves the other and either copy's write drops it for both; every check is the one it was (`kv-store.test.ts` loads a second copy with `vi.resetModules()`).
- **`system-info.ts`** — hostname, memory, CPU, temperature, disk, network stats via `/proc` and shell commands.
- **`auth.ts`** — session cookie generation/verification (HMAC-SHA256). The login lockout keys on `CF-Connecting-IP` when present (plus the always-charged `global` bucket); `scripts/proxy-peer.js`, attached to the HTTP server in `production-server.js` ahead of the access log, DELETES `cf-connecting-ip`/`cf-connecting-ipv6`/`true-client-ip` from any request whose socket peer is not loopback (127/8, ::1, ::ffff:127.x) — cloudflared is the only legitimate writer of those headers and it connects from loopback (`scripts/run-tunnel.sh` targets localhost:80) — so a LAN client lands on `global` like a header-less one and can neither dodge the escalation with a fresh bucket per request nor lock the owner's tunnel bucket for 24 h; loopback trust also trusts the box's own processes, which already act as the owner.
- **`owner-session.ts`** — "is the PERSON asking, or the agent?". Accepts a session cookie only, and is what stops the MCP bearer from opening the approval gate.
- **`process-store.ts`** — one object per PROCESS, on `globalThis` under `Symbol.for("clawbox.process-store")`, keyed by the thing the state belongs to rather than by the module. It exists because module-level `let` is NOT process-wide on this box: Next compiles `src/instrumentation.ts` in a layer of its own, so the boot hook's `require("./lib/coding-agent")` and a route handler's `import "@/lib/coding-agent"` are two DIFFERENT modules inside the one web-server process — read off the production build of 2026-09-13, `src/lib/coding-agent.ts` is emitted as module id 79687 in the chunk `instrumentation.js` loads and as 26377 in the chunk every app route loads, and Turbopack's module cache is keyed by that id (`src/lib/config-store.ts` is duplicated the same way, and so is everything else the boot hook reaches; `pgrep` shows one `clawbox-web`, so nothing about the process list gives this away). The runs store is its first caller: with the state per copy, the boot hook reattached and settled a run that survived a restart on its own array while the routes' copy answered `running`/`commit: null` for ever from the snapshot the Coding Agent window's 5 s poll had frozen mid-reattach — which cost a parallel slot (at `maxParallelRuns: 1`, every new run refused) and whose next write put that older snapshot back over the settled record on disk, so the NEXT boot settled a finished run as "the box restarted while the run was live" over work that was already merged. A module whose copies must agree — because they hold the handles on live work, or because both of them WRITE the same file — keeps its mutable state here, and so does one whose copies would each hold a parsed copy of the same file (`kv-store.ts`'s snapshot).
- **`gateway-proxy.ts`** — fetch gateway HTML, inject ClawBox nav bar + auth token.
- **`i18n.tsx`** — i18n context provider with browser language detection. Figures follow the UI locale too: `format-bytes.ts` and `clawkeep-ui.tsx`'s `formatBytes(n, locale)` and the System page's `localeFixed` print "24,1 GB" on a German desktop (English by default for lib and server callers, whose figure must not depend on where the process runs); the German relative-time strings put a space between number and unit ("in 16 Std 32 Min"); the ClawBox AI tier names the chat's model chip draws come from `CLAWBOX_AI_TIER_TEXT_KEYS` in `clawbox-ai-models.ts` (the Max tier IS `ai.planNameMax`, so the chip and the Providers page cannot call one plan two things), and the Voice tab's voice descriptors are `settings.voice.name.*` keys.
- **`translations.ts`** — translation strings for 10 languages (en, de, es, fr, it, ja, nl, sv, zh, bg): the SOURCE tables, what the tests read. What a page LOADS is one chunk per locale: **`translation-chunks.ts`** `loadLocaleTable(locale)` imports `translations-generated/<locale>.ts` (each locale laid over English, one key per line, ~300 KB; a module rather than JSON so a line naming an example home path can carry its `public-hygiene: allow` marker, which the generator writes) instead of the 3.5 MB aggregate every locale used to share (2026-10-27: the chunk was the last script before the desktop's load event, 1.15 s of parse on an x86 laptop). The modules are generated by `bun run gen:translations` (`scripts/gen-translation-chunks.ts`) and COMMITTED; `src/tests/unit/translation-chunks.test.ts` fails when they drift from the source tables, naming that command. Edit a translation → run it → commit both. `I18nProvider` falls back to the aggregate import when a chunk fails to load.
- **`tamagotchi.ts`** — mascot AI personality line generation.
- **`client-kv.ts`** — the browser's synchronous cache of `/setup-api/kv` (`data/kv.json`), filled once by `init()`. Writes are THROTTLED, not debounced: the first arms one 500 ms flush that carries everything set or removed before it, so a key reaches the box at most half a second later (a caller that writes every frame coalesces on its own side, as the mascot does). What is still waiting goes out at once on `pagehide` and on the page turning hidden (`flush()`), as `keepalive` requests that outlive the page — the timer never fires after a reload has begun, so the last half-second of writes used to be lost; a body past ~60 KB, or a keepalive the browser refuses (its 64 KiB is shared with the desktop-state save going out at the same moment), goes as an ordinary request.
- **`wifi-utils.ts`** — WiFi scan result parsing.
