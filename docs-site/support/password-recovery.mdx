ClawBox has **one human password**: the browser login and SSH check the very same Linux
system password (account `clawbox`) — see
[Authentication](/technical/authentication#the-one-password). So "I forgot the box
password" and "I can't SSH" are usually the same problem, and this page assumes both.
SSH is **off by default** and only works once the owner has turned it on in
**Settings → System → Remote access (SSH)**. If you *can* still get a terminal on the box
— the Terminal app, a saved SSH key, a remembered password —
you don't need this page: reset the password in ten seconds with
[Recovery option A](/support/recovery#a--reset-the-password-10-seconds-no-data-loss).

## What the password actually is

There is **no default password**. A new box ships with no password at all, and the only
credentials printed on it — the sticker's Wi-Fi QR code and hotspot password — are unique
to that box and only join its setup hotspot. The password only ever changes in four
places: the wizard's **Security** step, **Settings → System → Change password**, `sudo
passwd clawbox` in a terminal, and a factory reset (which removes it). Updates and
reboots never touch it:

| Device state | The password is |
|---|---|
| Brand new, wizard never finished | **None** — the wizard runs without any login |
| Set up and in use | Whatever was set in the wizard's **Security** step (or changed later in Settings) |
| After a **completed** factory reset | **None** — the box is back on its sticker hotspot with the wizard waiting |
| After a factory reset that **failed partway** | **Still the owner's password** |

Boxes made before per-device stickers were built with a published password, `clawbox`;
such a box counts as unowned until the wizard sets a real password, and never turns SSH
on with it.

<Warning>
The last row bites in real support cases. The factory reset deliberately resets the
password (and drops your Wi-Fi) **last**, only after every file wipe has succeeded — a
reset that stops early must leave the box reachable and retryable, not stranded offline.
So a reset that reported an error, lost power, or never finished leaves the password
exactly what it was before: the one set in the wizard. If "the box was reset" but the
wizard still asks for a login, **try the owner's original password** — it almost
certainly still applies.
</Warning>

Two rarer corners, for completeness:

- **Reset completed but a login is still asked for.** The password-removal step of a
  factory reset is best-effort: if it fails, the reset still finishes and reboots rather
  than stranding the box. Try the previous owner password; the wizard's Security step
  overwrites it either way.
- **You know the password but the browser rejects it** (and you can't check over SSH).
  Try a private/incognito window and type it by hand — stale browser autofill is the
  most common cause. The full ladder is in
  [Troubleshooting](/support/troubleshooting#the-browser-rejects-my-password-but-ssh-accepts-it).

## First, reach the box

Recovery starts with getting the ClawBox screen in front of you. In order of
reliability:

1. **`http://YOUR_BOX_IP`** — the IP from your router's connected-devices list (the box
   shows up as `clawbox`), or the one you bookmarked during setup. Plain HTTP, port 80,
   nothing after the IP.
2. **`http://clawbox.local`** — convenient but not universal; it fails on many Windows
   machines and behind VPNs. See
   [Networking](/technical/networking#why-clawboxlocal-sometimes-fails--and-what-to-do).
3. **The setup hotspot** — if the box is broadcasting its setup Wi-Fi network (the
   `ClawBox-XXXX` name on its sticker; `ClawBox-Setup` on boxes made before stickers), scan
   the sticker's QR code or join with the sticker password and open
   **`http://10.42.0.1`** (fallback `http://10.43.0.1` if your home network already uses
   that range). Lost the sticker? [Support](mailto:yanko@idrobots.com) can recover the
   box's hotspot credentials once they have verified your order. A box in hotspot mode has either been factory
   reset or lost your network — either way the wizard is waiting there.

## Recovery without SSH

Work top to bottom — each step is less convenient than the one before it.

<Steps>
  <Step title="Look for the password you set">
    Check your password manager and your browser's saved passwords for the box's IP or
    `clawbox.local` before declaring the wizard password lost — the browser you set the
    box up with very often kept it.
  </Step>
  <Step title="Find a device that is still logged in">
    Browser sessions last up to 24 hours, so a tab that talked to the box recently — the
    phone you set it up with, a laptop at home — may still be signed in. A live session
    is all you need: factory reset from the UI requires being logged in, **not**
    re-typing the password.

    From the logged-in device, open **Settings → System → Factory reset**, run it, and
    let it finish completely — a completed reset ends with the box rebooting into its
    sticker hotspot. Then re-run setup and choose a new password at the
    Security step. If the box instead lands back in the wizard **without** having
    rebooted, the reset did not complete — see
    [below](#if-the-factory-reset-fails-partway).
  </Step>
  <Step title="No session anywhere: factory reset is the remaining path">
    With no password and no live session, the box cannot be administered — by design:
    the login has no "forgot password" bypass, because anyone on your network could use
    it. What remains is a factory reset, and without a login the UI won't offer you one.
    Contact [support](mailto:yanko@idrobots.com) — a reflash restores the box to its
    out-of-the-box state (everything on it is erased, exactly like a factory reset).
  </Step>
</Steps>

<Info>
**What a factory reset erases:** AI provider keys, chats and agent state, Telegram
pairing, backups pairing, saved Wi-Fi, downloaded models, files in
Documents/Downloads/Desktop, SSH keys, and all settings. The offline on-device model
weights and the network hardware config survive, so the box comes back functional. The
full list, and what deliberately survives, is in
[Recovery option D](/support/recovery#d--factory-reset-wipes-everything). After a
completed reset the box has **no password** and SSH is **off**; it reboots into its
sticker hotspot (the same QR code and password as on day one) and the wizard runs
**without a login** — you set the new password at the Security step.
</Info>

## If the factory reset fails partway

A reset that cannot delete every file **stops before anything
connectivity-destructive happens**: no Wi-Fi is dropped, the password is not reset,
and the box does not reboot. That ordering is deliberate — a reset that stops early
must leave the box reachable rather than stranded offline — but it also produces the
single most confusing state a ClawBox can be in, because on screen the reset can
*look* like it finished and drop you into the setup wizard anyway.

You can tell a reset did **not** complete by any of these:

- The box **never went down** — no reboot, and the setup hotspot never
  appeared. A completed reset always ends in a reboot into the hotspot.
- The box is **still on your Wi-Fi** at its old address.
- The setup wizard loads, but its steps fail with **"Authentication required"**.
- The **owner's original password** is still accepted.

That last point is the whole story: the half-cleared box still has an owner — the old
password — and it correctly refuses to hand itself to whoever happens to be on the
network. There is no browser-only way out of this state. If SSH was turned on, connect
with `ssh clawbox@YOUR_BOX_IP` using the **owner's original password**, then either:

1. **Remove the password** — run `sudo usermod -p '!' clawbox`. The box then counts as
   "no owner", so the wizard immediately works again: its update step repairs the
   software, and its Security step sets your new password. Do this right away — until
   that Security step, anyone on the hotspot or your network could run the wizard; or
2. **Finish the wipe by hand** — the step-by-step commands are in
   [Recovery D → Over SSH](/support/recovery#over-ssh-when-you-cant-log-in-to-the-ui).

If SSH was off, or the owner's password is truly lost too, it's a reflash;
contact [support](mailto:yanko@idrobots.com).

## Do I actually need SSH?

| Situation | SSH needed? |
|---|---|
| Forgot the password, box otherwise working | **No** — factory reset from any still-logged-in device |
| Box was factory reset and is in hotspot mode | **No** — scan the sticker QR (or join with the sticker password), open `http://10.42.0.1`, run the wizard (no login asked) |
| Fresh box, first setup | **No** — the wizard needs no login |
| Know the password, browser rejects it | **No** for the first steps of the [login ladder](/support/troubleshooting#the-browser-rejects-my-password-but-ssh-accepts-it); the deeper diagnostics use SSH |
| Reset was interrupted and the box later restarted (power restored, manual reboot) | **Yes**, if it was turned on — SSH with the owner's original password, then see [above](#if-the-factory-reset-fails-partway); otherwise [support](mailto:yanko@idrobots.com) |
| No password, no session, no SSH | Neither helps — [support](mailto:yanko@idrobots.com) / reflash |
