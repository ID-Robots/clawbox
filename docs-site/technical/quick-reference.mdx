Everything load-bearing about a ClawBox on one page. Facts only — explanations live in the linked chapters.

## Identity

| Fact | Value |
|---|---|
| Product | ClawBox — AI appliance OS on NVIDIA Jetson (Ubuntu 22.04 aarch64) |
| Edition | `openclaw` \| `hermes` \| `dual`, from the root-owned `/etc/clawbox/edition.env`. Print it with `bun run /home/clawbox/clawbox/mcp/clawbox-cli.ts edition` |
| Repo | `github.com/ID-Robots/clawbox` · releases = `vX.Y.Z` tags on `main` · integration branch `beta` |
| System user | `clawbox` (uid 1000) · one password for SSH **and** browser login |
| Web UI | `http://<box-ip>` (port 80) · `http://clawbox.local` when mDNS works |
| Setup hotspot | SSID `ClawBox-Setup` → `http://10.42.0.1` (fallback subnet `10.43.0.1`) |
| Stack | Next.js 16 / React 19 / Node 22 runtime / Bun builds · AI harness: OpenClaw gateway (npm-pinned) on OpenClaw/dual, Hermes CLI + dashboard on Hermes/dual |

## Ports

Inbound is **default-deny** (ufw). "LAN" below means *private IPv4 source ranges only* (10/8, 172.16/12, 192.168/16, 169.254/16, 100.64/10) — anything else on IPv4 is dropped. IPv6 is not source-scoped. Full rules: [Networking → Firewall](/technical/networking#firewall).

| Port | Service | Exposure |
|---|---|---|
| 80 | Web OS (`clawbox-setup`) — UI, login, `/setup-api/*`, proxies to gateway | LAN |
| 443 | HTTPS (only if certs are installed at `data/certs/`) | LAN (private ranges) |
| 18789 | OpenClaw gateway — **OpenClaw/dual only** | LAN, token-gated — **never browse it directly**. Closed on Hermes |
| 8090 | Hermes dashboard auth proxy — **Hermes/dual only** | LAN, ClawBox-session-gated |
| 9119 | Hermes dashboard itself | `127.0.0.2` loopback |
| 22 | SSH | LAN |
| 3006 | Terminal WS — an **unauthenticated PTY** if reached directly | **Closed to the LAN** — use the session-gated `/terminal-ws` on port 80 |
| 5900 / 6080 | VNC / noVNC websockify | localhost only — reach it through `/novnc-ws` on port 80 |
| 18800 | Chromium CDP (AI browser) | localhost |
| 11434 | Ollama | localhost |
| 8080 / 8880 | llama.cpp / Kokoro TTS | localhost |
| 5353/udp · 67/udp · 53 | mDNS (`clawbox.local`) · DHCP on the AP interface · captive-portal DNS | open (5353 from anywhere; 53 from `10.42.0.0/24`, `10.43.0.0/24`) |

Also closed at the firewall: **631** CUPS (left running — loopback printing still works), **111** rpcbind (additionally disabled + masked), **8384** Syncthing if present, and anything else binding `0.0.0.0`.

## Paths

| Path | Contents |
|---|---|
| `/home/clawbox/clawbox` | App (git checkout) |
| `…/clawbox/data/` | Device state: `config.json`, `kv.json`, `.session-secret`, `.mcp-token`, `network.env`, `llamacpp/` (offline weights), `cloudflared/` (tunnel URL + device id) — survives updates, wiped by factory reset **except `network.env` and `llamacpp/models`** |
| `…/clawbox/.env` | App env — survives everything |
| `…/clawbox/.update-branch` | Channel pin (`beta`) — survives everything |
| `…/clawbox/config/openclaw-target.txt` | Pinned OpenClaw version |
| `/etc/clawbox/edition.env` | Root-owned edition lock — survives updates **and** factory reset |
| `~/.clawkeep/` | Backup pairing/config/passphrase (ClawKeep is OpenClaw/dual only) |

**OpenClaw / dual editions only**

| Path | Contents |
|---|---|

| `~/.openclaw/agents/main/agent/auth-profiles.json` | **Real provider credentials** |
| `~/.openclaw/agents/<agent>/agent/codex-home/auth.json` | ChatGPT-subscription session (synced per-agent) |
| `~/.openclaw/credentials/telegram-*.json` | Telegram pairing approvals |
| `~/.npm-global/bin/openclaw` | Gateway binary |

**Hermes / dual editions only**

| Path | Contents |
|---|---|
| `~/.local/bin/hermes` | Harness shim into `~/.hermes/hermes-agent/venv` |
| `~/.hermes/config.yaml` | Harness config + `mcp_servers.clawbox` (0600). Every writer rewrites the whole file — comments are not preserved |
| `~/.hermes/.env`, `~/.hermes/auth.json` | **Provider keys and OAuth tokens** |
| `~/.hermes/hermes-agent/` | The agent checkout + venv — **kept** by factory reset |
| `data/.hermes-dashboard-pw` | Dashboard auth material |

## Services (systemd)

**Every edition:** `clawbox-setup` (web, port 80) · `clawbox-ap` (+`-watchdog.timer`) · `clawbox-vnc` + `clawbox-websockify` · `clawbox-browser` (CDP, on demand) · `clawbox-heartbeat.timer` (+ `.service`) · `clawbox-tunnel` (optional, off by default) · `clawbox-performance` · `clawbox-root-update@<step>` (privileged installer steps) · `ollama`.

**OpenClaw / dual:** `clawbox-gateway` (pre-start self-heal script).
**Hermes / dual:** `clawbox-hermes-dashboard` · `clawbox-hermes-dashboard-proxy`. On Hermes the gateway unit is **masked** — an active `clawbox-gateway` there is a hard install failure.

## Commands (over SSH)

```bash
# Which edition is this?
cat /etc/clawbox/edition.env

# Health / logs — every edition
systemctl status clawbox-setup --no-pager
journalctl -u clawbox-setup -n 50 --no-pager      # web/login

# Health / logs — OpenClaw / dual
systemctl status clawbox-gateway --no-pager
journalctl -u clawbox-gateway -n 50 --no-pager    # AI/providers/channels
sudo systemctl restart clawbox-setup clawbox-gateway

# Health / logs — Hermes / dual (the gateway unit is masked; restarting it fails)
journalctl -u clawbox-hermes-dashboard -n 50 --no-pager
sudo systemctl restart clawbox-setup clawbox-hermes-dashboard clawbox-hermes-dashboard-proxy

# Update (full, correct way) — == sudo bash /home/clawbox/clawbox/install.sh
bun run /home/clawbox/clawbox/mcp/clawbox-cli.ts update   # asks for sudo itself; refused on Hermes
# Hermes: use Settings → System Update instead.

# Targeted repairs — OpenClaw / dual only; both print '[hermes edition] skipping …' and exit on Hermes
sudo bash install.sh --step gateway_setup     # fixes 'gateway token mismatch'
sudo bash install.sh --step openclaw_install  # fixes stale core / 'Unrecognized key' / plugin skew

# Password
sudo passwd clawbox            # new password, effective everywhere immediately

# Channel
echo beta > /home/clawbox/clawbox/.update-branch   # opt into beta (delete file to leave)

# Login check (exactly what the web app does)
read -rsp 'PW: ' PW; echo; printf '%s\0' "$PW" | /usr/sbin/unix_chkpwd clawbox nullok; echo "exit=$?"; unset PW

# Login API check (bypasses browser)
curl -sS -X POST http://localhost/login-api -H 'Content-Type: application/json' -d '{"password":"…","duration":1200}'
```

## Key API endpoints (`/setup-api/*`, session-cookie or MCP-bearer auth)

| Endpoint | Purpose |
|---|---|
| `POST /login-api` `{password,duration}` | Login → `clawbox_session` cookie (durations 1200/21600/43200/86400 s) |
| `GET /setup-api/system/info` · `system/stats` | Device info / live metrics |
| `POST /setup-api/system/credentials` | Change password |
| `POST /setup-api/system/power` | Restart/shutdown |
| `GET /setup-api/update/versions?force=1` | Version check (fresh) |
| `POST /setup-api/update/run` · `GET update/status` | Run update / poll progress |
| `POST /setup-api/update/reset` | Reset-to-channel & update *(beta)* |
| `GET/POST /setup-api/system/update-branch` | Read/set channel |
| `POST /setup-api/ai-models/configure` | Write provider config |
| `GET /setup-api/ai-models/status` · `catalog?provider=…` | Provider status / live model catalog |
| `POST /setup-api/telegram/configure` · `pairing` | Bot token / approve pairing codes |
| `GET /setup-api/gateway/health` · `ws-config` | Gateway health / WS URL + token — **OpenClaw/dual**; on Hermes health always reports unavailable |
| `/setup-api/hermes/{chat,models,provider-key,oauth,clawai,skills}` · `/setup-api/harness/active` | **Hermes/dual** — chat, model catalog, provider key/OAuth, ClawBox AI, Skills |
| `GET /setup-api/portal/status` · `POST portal/start` · `portal/stop` | Remote access (Cloudflare Quick Tunnel). **Not** `/setup-api/tunnel/*`, which the UI does not use |
| `POST /setup-api/setup/reset` | **Factory reset** (destructive) — needs a session **and** `{ password, confirm: "RESET" }`; the password is throttled like `/login-api` |
| `/setup-api/wifi/*` · `files/*` · `apps/*` · `clawkeep/*` · `code/*` · `preferences` | Wi-Fi, file manager, app store, backups, code projects, prefs (all under `/setup-api/`) |

## Gotchas (hard-won)

1. **`:18789` never accepts your password** — it's the OpenClaw gateway (OpenClaw/dual); use plain `http://<ip>`. On Hermes it is closed entirely (connection refused) and the equivalent surface is the session-gated dashboard proxy on `:8090`.
2. **Browser login ≠ separate password** — same Linux password as SSH; failures are usually autofill, `unix_chkpwd` perms (`-rwxr-sr-x root shadow`), a stale build, or password encoding. Ladder: [Troubleshooting](/support/troubleshooting#the-browser-rejects-my-password-but-ssh-accepts-it).
3. **`git pull` is not an update** — always finish with `sudo bash install.sh`; otherwise service files + the agent core go stale (`token mismatch`, `Unrecognized key`). Hard-sync to the box's own `.update-branch`, not a hardcoded `main`.
4. **Local commits silently block updates** on stable ≤ current release ("up to date" forever); beta shows "Updates paused" + one-click reset. Manual fix = hard-sync ([Recovery C](/support/recovery#c--safe-reinstall-1015-minutes-no-data-loss)).
5. **Two OpenAI lanes (OpenClaw/dual)**: both are `openai/…` since OpenClaw 2 — API key = profile `openai:default` + `sk-…`; ChatGPT subscription = OAuth profile `openai:chatgpt` plus `agents.defaults.models."openai/<id>".agentRuntime.id = "codex"`. Different catalogs (the API lane carries the `-pro` tiers in addition to `gpt-5.4/5.5/5.6`; the subscription carries no `-pro`), different credentials. The `codex/…` namespace is retired (`Unknown model`); `doctor --fix` rewrites it. Stale-key 401s after switching are self-healed on beta. **On Hermes there is no OpenAI API-key lane at all** — OpenAI is sign-in (Codex) only, and the key providers are OpenRouter, Anthropic, Gemini, z.ai and Kimi.
6. **Secrets live in `auth-profiles.json`** (OpenClaw/dual), not `openclaw.json` (metadata only). The codex session is *additionally* per-agent in `codex-home/auth.json`. On Hermes, credentials are held by `hermes auth add` under `~/.hermes`.
7. **`clawbox.local` failing ≠ box down** — mDNS/Windows/router multicast issue; the IP always works.
8. **The last update step reboots the box** — 1–2 min offline is normal, not a hang.
9. **Factory reset password is `clawbox`** — and the box comes back in AP mode (`ClawBox-Setup` → `10.42.0.1`). It keeps `data/network.env`, `data/llamacpp/models` and `~/.hermes/hermes-agent`, and the portal device id is re-derived from `/etc/machine-id`. Never hand-roll it with `rm -rf ~/.hermes` or `rm -rf data/*` — see [Recovery D](/support/recovery#d--factory-reset-wipes-everything).
10. **Version label ≠ running code** — `package.json` is read live; verify actual deployment via `.next/BUILD_ID` mtime.
